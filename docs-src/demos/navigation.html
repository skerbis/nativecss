Off-Canvas und automatischer Kompakt-Modus

Eine Nav-Struktur, zwei Darstellungen: in der Zeile oder hinter der Menü-Schaltfläche als Off-Canvas-Panel (<dialog>). Es entscheidet der Platz, nicht eine feste Breite - in zwei Stufen:

  1. Ohne JavaScript: Container Query. .ncss-topbar-inner (bzw. .ncss-nav-container für eigene Leisten) ist ein Container. Die Seite nennt mit data-ncss-nav-fit="52", wie breit die Zeile in rem sein muss (das CMS schätzt das aus dem Menü, Formel unten); ist sie schmaler, erscheint die Menü-Schaltfläche. Ohne Angabe gilt 64rem. Weil rem mit Schriftgröße und Zoom wächst, stimmt der Zustand schon beim ersten Zeichnen.
  2. Mit js/nav.js: Nachmessen. Das Skript prüft per ResizeObserver, ob die Liste wirklich in eine Zeile neben Marke und Aktionen passt (Textabstände, Ersatzschriften, Übersetzungen), und setzt data-ncss-nav-auto="inline" bzw. "compact". Dieser Zustand hat Vorrang vor der Container Query - die beiden kämpfen nicht gegeneinander.
<script src="js/nav.js" defer></script>  <!-- optional, im <head> -->

<header class="ncss-topbar"><div class="ncss-topbar-inner">
  <a class="ncss-topbar-brand" href="/">Marke</a>
  <nav class="ncss-nav" aria-label="Hauptnavigation" data-ncss-nav-fit="52">
    <button type="button" class="ncss-nav-toggle" command="show-modal" commandfor="navPanel" aria-label="Menü öffnen">☰</button>
    <dialog id="navPanel" class="ncss-nav-panel ncss-offcanvas ncss-offcanvas--start" aria-label="Menü">
      <button type="button" class="ncss-dialog-close" command="close" commandfor="navPanel" aria-label="Menü schließen">&times;</button>
      <ul class="ncss-nav-list"> ... </ul>
    </dialog>
  </nav>
  <div class="ncss-topbar-actions"> Suche, Button ... </div>
</div></header>

Live - Regler ziehen (jeder Rahmen ist ein eigener Viewport). Oben mit js/nav.js, unten dasselbe Markup ohne JavaScript: nur die Container Query mit data-ncss-nav-fit="52".

Schwelle schätzen (CMS, Server)

Benötigte Breite in rem = Marke + Summe der Punkte + Aktionen + Abstände. Werte für die Standard-Tokens: je Punkt Zeichen × 0,55 + 2,4 (mit Untermenü + 1,2), Marke als Text Zeichen × 0,65 (Logo: seine Breite), Button Zeichen × 0,55 + 2,5, Symbol-Button 2,75, Suchfeld seine Breite, dazu 1,75 je Lücke zwischen den Teilen der Zeile. Ergebnis auf ein Vielfaches von 4 aufrunden. Lieber etwas zu groß als zu klein: zu groß heißt nur, dass die Menü-Schaltfläche etwas früher erscheint; mit js/nav.js wird ohnehin genau nachgemessen. Eigene Schrift, Abstände oder Versalien: Faktoren anpassen (einmal im Browser die Breite messen, bei der js/nav.js umschaltet).

/** Schwelle für data-ncss-nav-fit (rem), z.B. aus dem Menü-Baum des CMS */
function ncss_nav_fit(array $items, float $brand, float $actions, int $parts = 3): int
{
    $rem = $brand + $actions + 1.75 * ($parts - 1);   // Marke, Aktionen, Lücken der Zeile
    foreach ($items as $item) {
        $rem += mb_strlen($item['label']) * 0.55 + 2.4 + (empty($item['children']) ? 0 : 1.2);
    }
    return (int) ceil($rem / 4) * 4;
}

$fit = ncss_nav_fit($menu, mb_strlen($siteName) * 0.65, 16);   // Suche 8rem + Button
echo $fit > 120
    ? '<nav class="ncss-nav ncss-nav--compact" …>'
    : '<nav class="ncss-nav" data-ncss-nav-fit="' . max(24, $fit) . '" …>';

Eigenes CSS für den Kompakt-Zustand

Alle Wege setzen denselben Schalter --ncss-nav-compact (eine leere Custom Property, "Space Toggle") - an der Nav und an ihren Geschwistern in der Zeile. Eigene Regeln stehen damit nur einmal da und stimmen mit und ohne JavaScript:

/* Button nur in der Zeile, im Kompakt-Zustand ausblenden */
.mein-cta {
  --_d: var(--ncss-nav-compact) none;   /* Wert für "kompakt" */
  display: var(--_d, inline-flex);      /* Wert für "Zeile" */
}

Ist der Schalter gesetzt, gilt der Wert hinter var(--ncss-nav-compact), sonst der Rückfallwert. Für Elemente außerhalb der Zeile (z.B. eine Seitenleiste) bleibt der Zustand von js/nav.js (.ncss-nav[data-ncss-nav-auto="compact"]) bzw. eine eigene Media Query. <ncss-nav-priority> hat eigene Logik und wird nicht gemessen.

Barrierefreiheit: Die Menü-Schaltfläche braucht einen Namen (aria-label); js/nav.js ergänzt aria-controls und hält aria-expanded passend zum Panel. Liegt der Tastaturfokus in der Liste, wenn sie zusammenklappt, wandert er auf die Menü-Schaltfläche; wird es wieder breit, schließt ein offenes Panel und der Fokus bleibt auf dem Link. Fokusfalle nur im offenen modalen Panel, Escape schließt es und gibt den Fokus an die Schaltfläche zurück. Die Messung reagiert auch auf größere Schrift, Zoom und Textabstände (WCAG 1.4.4, 1.4.10, 1.4.12) - sie beobachtet den Inhalt, nicht nur die Fensterbreite. Ein-/Ausblenden folgt prefers-reduced-motion.

Slide-Drilldown für mobile Untermenüs (Opt-in, JS)

<ncss-nav-drilldown> (components/nav-drilldown.css + js/nav-drilldown.js) - statt inline aufzuklappen, schiebt sich beim Antippen eines Elternpunkts das GANZE Panel auf die Kindpunkte um (wie iOS-Einstellungen), mit einem "Zurück"-Punkt oben. Nur mobil relevant, IDENTISCHES Markup wie der normale verschachtelte Dropdown - ohne JS klappt es normal inline auf. Ein Elternpunkt bleibt zusätzlich als eigene Seite aufrufbar, wenn <summary> einen echten <a> enthält (siehe "Produkte" unten) - ein Klick auf den Linktext navigiert, ein Klick auf den Chevron drillt rein. 

<ncss-nav-drilldown>
  <ul class="ncss-nav-list">
    <li class="ncss-nav-item">
      <details class="ncss-nav-dropdown">
        <summary><a href="/produkte">Produkte</a></summary>
        <ul class="ncss-nav-submenu">
          <li><a href="/produkte/a">Produkt A</a></li>
        </ul>
      </details>
    </li>
  </ul>
</ncss-nav-drilldown>

Leiste beim Scrollen aus-/einblenden

Rein native CSS Scroll-State-Container-Query (@container scroll-state(scrolled: block-end)), kein JS, kein Scroll-Event-Listener. Auf DIESER Seite (echtes Seiten-Scroll) runter- scrollen - die Leiste unten blendet aus; wieder hochscrollen, sie kommt zurück. Noch nicht in jedem Browser unterstützt (@supports-Gate) - ohne Unterstützung bleibt sie einfach dauerhaft sichtbar, kein kaputtes Verhalten.
