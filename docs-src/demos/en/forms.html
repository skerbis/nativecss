Input-Group

Form controls visually merged into ONE unit (components/input-group.css) - shared border instead of a gap, only the outer corners rounded. Two cases: field + button (search bar) and several fields side by side (first name/last name).

Accessibility: placeholder is NOT a substitute for a label - it disappears on input and is not reliably announced as the field name by every screen reader. Every field needs a real <label>, visually hidden via .ncss-visually-hidden if needed. The label goes BEFORE the .ncss-input-group as a sibling, not inside it as a child - otherwise it wrongly counts as :first-child and the corner rounding lands on the invisible label instead of the first real field.

<label class="ncss-visually-hidden" for="live-search">Search term</label>
<div class="ncss-input-group">
  <input class="ncss-input" type="search" id="live-search" placeholder="Search term…">
  <button type="submit" class="ncss-btn ncss-btn--primary">Search</button>
</div>

<!-- Several directly merged fields with no room for a visible/hidden
     sibling label per field: aria-label directly on the <input> is the right,
     WCAG-compliant technique here (no structural change to the input group needed). -->
<div class="ncss-input-group">
  <input class="ncss-input" aria-label="First name" placeholder="First name">
  <input class="ncss-input" aria-label="Last name" placeholder="Last name">
</div>

Live search

Suggestions while you type, grouped and keyboard-operable (arrow keys, Enter, Esc) - components/livesearch.css + js/livesearch.js, WAI-ARIA combobox pattern. This demo uses a static JSON file in client mode (data-mode="client"); normally a server endpoint returns pre-filtered results. Without JS it stays a regular search form. Try e.g. “nav”, “farb” or “glass”.

<form class="ncss-livesearch" action="/suche/" role="search" data-ncss-livesearch="/api/suche">
  <label class="ncss-visually-hidden" for="live-q">Search</label>
  <input id="live-q" class="ncss-input" type="search" name="q">
  <div class="ncss-livesearch-results" hidden></div>
</form>
<script src="dist/js/livesearch.js" defer></script>

File upload

The input type with the biggest cross-browser differences - Chrome/Edge/Safari draw their own button + file name, Firefox a "Browse…" button. ::file-selector-button (+ ::-webkit-file-upload-button for older Safari versions) gives the button the same look as .ncss-btn--secondary.

More field types

All via the same .ncss-input base rule, with targeted additions per type where browsers bring their own pseudo-elements (color swatch, calendar/clock icon, clear icon in search).

<input list> + <datalist> - an editable text field WITH a suggestion list (unlike <select>, which only allows choosing without free input). .ncss-input applies without a special rule, since it targets every <input> generically. The native suggestion list itself is pure browser UI - not stylable via CSS in any browser. With the opt-in js/combobox.js (included here) it is replaced by a real, styled dropdown list (original markup unchanged, full native functionality remains without JS).

Grouped fields

Native <fieldset>/<legend> instead of a custom "group" component - fully styled without its own class (like <blockquote> in base.css); otherwise the UA stylesheet's native 3D border would be the only remaining style break compared to the flat ncss fields.
