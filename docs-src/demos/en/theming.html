One file for all the important values - theme.css (repo root). Load it after ncss.css, override the values directly in it, don't touch any other file.

How it works

theme.css is deliberately UNLAYERED (no @layer of its own) - and per the spec, unlayered CSS always wins over any layered rule from ncss.css (layer tokens), regardless of selector specificity. A plain :root { --ncss-color-brand: ... } is enough, no !important needed.

Only the BASE/SEED values belong there (brand colors, base surfaces, fonts, radii, shadows, motion) - the color scales derived from them (--ncss-color-brand-100/-300/-700/-900/-on-soft) are computed via color-mix() from EXACTLY ONE base value and follow along automatically.

Live example

This box additionally loads theming-example.css - the same handful of seed values as a real theme.css, here just set locally on this area instead of on :root (a theme file can just as well recolor a single page area instead of the whole page). Button, card border/radius and focus ring react automatically, with no rules of their own for this theme.

Two pitfalls, relevant ONLY when applied locally (a real theme.css on :root is affected by NEITHER):

  • font-family is an inherited property; .ncss-btn doesn't declare it itself but inherits the already resolved value from body further up the tree - so setting --ncss-font-family-base here only as a custom property isn't enough, font-family: var(--ncss-font-family-base) must also be redeclared at this point (line below). Same pitfall as with .ncss-scheme-dark/-light, see helpers/surfaces.css.
  • The badges below DELIBERATELY keep the default color (blue/purple) - not a rendering bug but a real limitation: .ncss-badge uses --ncss-color-brand-100/-on-soft (the scale DERIVED via color-mix() in colors.css), and that is computed only ONCE on :root, then inherited as a finished value. Overriding --ncss-color-brand deeper in the tree does NOT recompute this already computed, inherited derivation - only rules that use var(--ncss-color-brand) (the seed itself) directly, like .ncss-btn--primary, react to a local override. A real theme.css on :root doesn't have this problem: there the whole scale IS computed fresh.

Card in the example theme

Different brand color, different radii, different font family - all via seven lines in theming-example.css.

Focusable (try the Tab key) 
.theming-demo-panel {
  --ncss-color-brand: light-dark(#b45309, #fb923c);
  --ncss-color-brand-contrast: light-dark(#ffffff, #1a1204);
  --ncss-color-brand-2: light-dark(#166534, #4ade80);
  --ncss-color-brand-2-contrast: light-dark(#ffffff, #06210f);
  --ncss-color-focus-ring: light-dark(#b45309, #fb923c);
  --ncss-radius-sm: 0.1rem;
  --ncss-radius-md: 0.2rem;
  --ncss-radius-lg: 0.3rem;
  --ncss-font-family-base: Georgia, "Times New Roman", serif;

  /* only needed when applied locally, see text above */
  font-family: var(--ncss-font-family-base);
}

Multiple themes

Repeat the same structure in another file (e.g. theme-sunset.css) and load it instead of theme.css depending on the project/domain - or use the [data-palette] convention in colors.css for a purely attribute-driven switch without a second file: <html data-palette="sunset">, see the Colors demo.
