Guides

Task-based, step-by-step examples, all reproducible live on this page. For the pure token/class reference, see the docs.

1. Build your own section

For your own pages, three building blocks are usually enough: a .ncss-container for the column width, .ncss-stack for vertical rhythm between the children, and if needed a .ncss-py-* class for extra inner padding at the top/bottom.

<section class="ncss-container ncss-stack ncss-py-lg">
  <h2>Title</h2>
  <p>Text ...</p>
  <button class="ncss-btn ncss-btn--primary">Action</button>
</section>

.ncss-stack sets gap: var(--ncss-space-md) between ALL direct children - no manual margin per element needed. For tighter/wider spacing use .ncss-stack--tight/--loose instead of inventing a new number.

2. Spacing: three levels, as needed

Before reaching for a new utility class, let alone a magic number, check in this order:

  1. Do nothing. base.css already gives paragraphs/headings/lists etc. a sensible margin-block-end - the normal case needs no class at all.
  2. Utility class. .ncss-py-*/.ncss-px-*/.ncss-mb-*/.ncss-gap-* (helpers/layout.css, four steps each: sm/md/lg/xl) cover most cases.
  3. Token directly, as a last resort. For a combination that doesn't exist as a class: style="padding-inline-start: var(--ncss-space-2xl)" is fine - it's a TOKEN, not a magic number. What is NOT fine: style="padding: 17px".

All three levels use the same --ncss-space-* tokens - these are already fluid (clamp()), so automatically "responsive" without breakpoints: the same spacing scales smoothly between a minimum and a maximum viewport width. Resize the window to see it:

.ncss-py-lg .ncss-px-lg - make the box narrower

3. Responsive grid without breakpoints

.ncss-grid is an intrinsic grid (repeat(auto-fit, minmax(var(--ncss-grid-min), 1fr))) - it counts columns based on the available width, not on fixed breakpoints. It automatically responds to the CONTAINER (not just the viewport), so it also works correctly in a narrow sidebar.

<div class="ncss-grid" style="--ncss-grid-min: 10rem;">
  <div>Card 1</div>
  <div>Card 2</div>
  <div>Card 3</div>
  <div>Card 4</div>
</div>

--ncss-grid-min is a custom-property parameter, not a decorative inline style (see conventions in the docs) - the higher the value, the sooner a column drops.

4. When you really need a breakpoint jump

Not every case is fluid - sometimes something should change fundamentally at a FIXED width (e.g. navigation switching from hamburger to full menu). For that, use the documented breakpoint convention from tokens.css, in its own @media rule:

.mein-element {
  background-color: var(--ncss-color-danger-100);
}
/* -- ncss breakpoint: md (768px) -- */
@media (min-width: 48rem) {
  .mein-element {
    background-color: var(--ncss-color-success-100);
  }
}

Live - make the BROWSER WINDOW narrower/wider than 768px (a real media query, not a container query, so an inner box won't respond here):

Red below 768px, green from 768px

Important: var() currently works in NO browser inside the @media condition itself (@media (min-width: var(--x)) is invalid) - the number (48rem) has to be written there directly. The comment -- ncss breakpoint: md -- in front of it records that it follows the documented convention instead of inventing a new number.

5. Set the focal point for cropped images

Wherever NativeCSS uses object-fit: cover (ratio helpers, card media, video), --ncss-focus-point (default center) controls the crop:

<div class="ncss-ratio-square" style="--ncss-focus-point: 20% 80%;">
  <img src="photo.jpg" alt="...">
</div>

Detailed example you can compare live: media.html#bilder.

6. Create your own component

  1. New file under components/, e.g. components/my-component.css.
  2. Use only var(--ncss-*) - no hard-coded values. If a token is missing, add it to tokens.css/colors.css first.
  3. Wrap the file content in @layer components { … } (like every file under components/) and import it in ncss.css: @import url("components/my-component.css"); - the layer then also applies when the file is loaded on its own via <link>.
  4. Verify with Playwright in a real browser - especially dark mode (contrast!).

A real example to study: components/sparkline.css (small, self-contained, a good template for the scope a single component should have).

7. Theme a new Web Awesome component

  1. Read the local reference docs FIRST: vendor/webawesome/dist-cdn/skills/webawesome/references/components/<name>.md - more reliable than the public docs site (see docs, pitfall 0).
  2. Check which --wa-color-*/--wa-* variables the component actually uses.
  3. Add them to webawesome-bridge.css, referencing only ncss tokens - no values of your own.
  4. Put the component tag into the markup once; the autoloader loads the rest automatically - no manual import needed.
  5. Verify in BOTH themes with Playwright (see docs, pitfall 2 - the most common bridge error source is dark-mode contrast).
