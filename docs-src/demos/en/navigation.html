Off-canvas and automatic compact mode

One nav structure, two presentations: in the row, or behind the menu button as an off-canvas panel (<dialog>). The available space decides, not a fixed width - in two stages:

  1. Without JavaScript: container query. .ncss-topbar-inner (or .ncss-nav-container for your own bars) is a container. The page states with data-ncss-nav-fit="52" how wide the row has to be in rem (the CMS estimates it from the menu, formula below); when it is narrower, the menu button appears. Without a value: 64rem. Because rem grows with font size and zoom, the state is right from the first paint.
  2. With js/nav.js: measuring. The script checks with ResizeObserver whether the list really fits into one row next to brand and actions (text spacing, fallback fonts, translations) and sets data-ncss-nav-auto="inline" or "compact". This state takes precedence over the container query - the two never fight.
<script src="js/nav.js" defer></script>  <!-- optional, in <head> -->

<header class="ncss-topbar"><div class="ncss-topbar-inner">
  <a class="ncss-topbar-brand" href="/">Brand</a>
  <nav class="ncss-nav" aria-label="Main navigation" data-ncss-nav-fit="52">
    <button type="button" class="ncss-nav-toggle" command="show-modal" commandfor="navPanel" aria-label="Open menu">☰</button>
    <dialog id="navPanel" class="ncss-nav-panel ncss-offcanvas ncss-offcanvas--start" aria-label="Menu">
      <button type="button" class="ncss-dialog-close" command="close" commandfor="navPanel" aria-label="Close menu">&times;</button>
      <ul class="ncss-nav-list"> ... </ul>
    </dialog>
  </nav>
  <div class="ncss-topbar-actions"> search, button ... </div>
</div></header>

Estimating the threshold (CMS, server)

Required width in rem = brand + sum of the items + actions + gaps. Values for the default tokens: per item characters × 0.55 + 2.4 (with submenu + 1.2), text brand characters × 0.65 (logo: its width), button characters × 0.55 + 2.5, icon button 2.75, search field its width, plus 1.75 per gap between the parts of the row. Round up to a multiple of 4. Rather too large than too small: too large only means the menu button appears a little earlier; with js/nav.js it is measured exactly anyway. Own font, spacing or capitals: adjust the factors (measure once in the browser at which width js/nav.js switches).

/** Threshold for data-ncss-nav-fit (rem), e.g. from the CMS menu tree */
function ncss_nav_fit(array $items, float $brand, float $actions, int $parts = 3): int
{
    $rem = $brand + $actions + 1.75 * ($parts - 1);   // brand, actions, gaps of the row
    foreach ($items as $item) {
        $rem += mb_strlen($item['label']) * 0.55 + 2.4 + (empty($item['children']) ? 0 : 1.2);
    }
    return (int) ceil($rem / 4) * 4;
}

$fit = ncss_nav_fit($menu, mb_strlen($siteName) * 0.65, 16);   // search 8rem + button
echo $fit > 120
    ? '<nav class="ncss-nav ncss-nav--compact" …>'
    : '<nav class="ncss-nav" data-ncss-nav-fit="' . max(24, $fit) . '" …>';

Your own CSS for the compact state

Every path sets the same switch --ncss-nav-compact (an empty custom property, "space toggle") - on the nav and on its siblings in the row. Your own rules are written once and are right with and without JavaScript:

/* Button only in the row, hidden in the compact state */
.my-cta {
  --_d: var(--ncss-nav-compact) none;   /* value for "compact" */
  display: var(--_d, inline-flex);      /* value for "row" */
}

When the switch is set, the value after var(--ncss-nav-compact) applies, otherwise the fallback. For elements outside the row (e.g. a sidebar) use the state of js/nav.js (.ncss-nav[data-ncss-nav-auto="compact"]) or your own media query. <ncss-nav-priority> has its own logic and is not measured.

Accessibility: the menu button needs a name (aria-label); js/nav.js adds aria-controls and keeps aria-expanded in sync with the panel. If keyboard focus is in the list when it collapses, it moves to the menu button; when there is room again an open panel closes and focus stays on the link. Focus is trapped only in the open modal panel, Escape closes it and returns focus to the button. Measuring also reacts to larger text, zoom and text spacing (WCAG 1.4.4, 1.4.10, 1.4.12) - it observes the content, not only the window width. Showing/hiding follows prefers-reduced-motion.

Slide drilldown for mobile submenus (opt-in, JS)

<ncss-nav-drilldown> (components/nav-drilldown.css + js/nav-drilldown.js) - instead of expanding inline, tapping a parent item slides the WHOLE panel over to its child items (like iOS Settings), with a "Back" item at the top. Only relevant on mobile, IDENTICAL markup to the regular nested dropdown - without JS it simply expands inline. A parent item also stays reachable as its own page if <summary> contains a real <a> (see "Products" below) - clicking the link text navigates, clicking the chevron drills in.
