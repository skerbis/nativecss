Off-canvas and automatic compact mode

One nav structure, two presentations: in the row, or behind the menu button as an off-canvas panel (<dialog>). With js/nav.js no fixed width decides, the available space does: the script measures with ResizeObserver whether the list fits into one row next to brand and actions. The list never wraps into a second row - a short nav stays in the row even on a phone, a long one collapses even on desktop.

<script src="js/nav.js" defer></script>  <!-- in <head>: state is known before the first paint -->

<header class="ncss-topbar"><div class="ncss-topbar-inner">
  <a class="ncss-topbar-brand" href="/">Brand</a>
  <nav class="ncss-nav" aria-label="Main navigation">
    <button type="button" class="ncss-nav-toggle" command="show-modal" commandfor="navPanel" aria-label="Open menu">☰</button>
    <dialog id="navPanel" class="ncss-nav-panel ncss-offcanvas ncss-offcanvas--start" aria-label="Menu">
      <button type="button" class="ncss-dialog-close" command="close" commandfor="navPanel" aria-label="Close menu">&times;</button>
      <ul class="ncss-nav-list"> ... </ul>
    </dialog>
  </nav>
  <div class="ncss-topbar-actions"> search, button ... </div>
</div></header>

MarkupEffect
(default) with js/nav.jsAutomatic: row while it fits, otherwise menu button. The script sets data-ncss-nav-auto="inline" or "compact" and reports every switch as the event ncss-nav-change (event.detail.compact).
.ncss-nav--compactAlways the menu button, at any width.
data-ncss-nav-auto="off"No measuring - fixed switch at 64rem (e.g. when other page CSS depends on the same threshold, like this website's top bar).
without JavaScriptFalls back to the media query at 64rem (above it a row that wraps when space runs out).

Your own CSS for the compact state (e.g. moving elements into the panel): .ncss-nav:is(.ncss-nav--compact, [data-ncss-nav-auto="compact"]) - plus the same rules in @media (max-width: 63.99rem) for pages without JavaScript. <ncss-nav-priority> and <ncss-nav-drilldown> have their own logic and are not measured.

Accessibility: the menu button needs a name (aria-label); js/nav.js adds aria-controls and keeps aria-expanded in sync with the panel. If keyboard focus is in the list when it collapses, it moves to the menu button; when there is room again an open panel closes and focus stays on the link. Focus is trapped only in the open modal panel, Escape closes it and returns focus to the button. Measuring also reacts to larger text, zoom and text spacing (WCAG 1.4.4, 1.4.10, 1.4.12) - it observes the content, not only the window width. Showing/hiding follows prefers-reduced-motion.

Many items: priority navigation (opt-in, JS)

<ncss-nav-priority> (custom element, components/nav-priority.css + js/nav-priority.js) automatically moves items that no longer fit on one line into a "More" dropdown via ResizeObserver - works for any number of items, no fixed breakpoint in the code. Without JS it is a plain passthrough (regular flex-wrap). 

<ncss-nav-priority>

Slide drilldown for mobile submenus (opt-in, JS)

<ncss-nav-drilldown> (components/nav-drilldown.css + js/nav-drilldown.js) - instead of expanding inline, tapping a parent item slides the WHOLE panel over to its child items (like iOS Settings), with a "Back" item at the top. Only relevant on mobile, IDENTICAL markup to the regular nested dropdown - without JS it simply expands inline. A parent item also stays reachable as its own page if <summary> contains a real <a> (see "Products" below) - clicking the link text navigates, clicking the chevron drills in. 

<ncss-nav-drilldown>
  <ul class="ncss-nav-list">
    <li class="ncss-nav-item">
      <details class="ncss-nav-dropdown">
        <summary><a href="/produkte">Products</a></summary>
        <ul class="ncss-nav-submenu">
          <li><a href="/produkte/a">Product A</a></li>
        </ul>
      </details>
    </li>
  </ul>
</ncss-nav-drilldown>
