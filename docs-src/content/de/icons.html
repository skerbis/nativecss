Kern-Icons

Eigene SVGs als CSS mask-image: kein Markup-Inhalt, kein Request, kein JavaScript. 24er-Raster mit runden Enden - Linien-Glyphen (Pfeile, Chevrons, plus/minus) etwas kräftiger als Piktogramme. Kachel anklicken kopiert das Markup.

<ncss-icon>: alle Phosphor-Icons

Lädt ein Icon aus vendor/phosphor/ (Phosphor Icons, MIT) und setzt es bereinigt als Inline-SVG mit fill="currentColor" ein. Jede Datei wird pro Seite nur einmal geladen. helpers/icons.css reserviert die Fläche schon vorher - nichts springt.

<link rel="stylesheet" href="dist/ncss.css">   <!-- oder nur dist/helpers/icons.css -->
<script src="dist/js/icon.js" defer></script>

<ncss-icon name="house"></ncss-icon>
<ncss-icon name="heart" weight="fill" label="Favorit"></ncss-icon>

Attribute

AttributWirkung
namePhosphor-Name, z.B. house, arrow-right, gear-six (Suche im Baukasten)
weightregular (Default), thin, light, bold, fill, duotone
labelmacht das Icon bedeutungstragend: role="img" + aria-label. Ohne label ist es dekorativ (aria-hidden="true").
srcstatt name eine beliebige eigene SVG-Datei laden (wird ebenfalls bereinigt)
data-ncss-icon-pathIcon-Ordner, auf dem Element oder einem Vorfahren (z.B. <html>), relativ zur Seite. Default: vendor/phosphor/ relativ zu dist/js/icon.js.

Events: ncss-icon-load und ncss-icon-error (bubbeln, detail.url).

Ohne JavaScript bleibt <ncss-icon> leer

Vor dem Laden des Scripts (oder ohne JS) ist das Element unsichtbar, die Fläche aber reserviert. Ein Icon, das Bedeutung trägt (z.B. ein Button ohne Text), deshalb als Kern-Icon oder per Sprite einsetzen - oder den Text daneben sichtbar lassen.

Eigener Icon-Pfad

<html lang="de" data-ncss-icon-path="/assets/phosphor/">
<!-- erwartet /assets/phosphor/regular/house.svg, /assets/phosphor/bold/house-bold.svg … -->
<ncss-icon src="/assets/logo-mark.svg" label="Logo"></ncss-icon>

SVG-Sprite: Phosphor ohne JavaScript

Ein Sprite ist eine SVG-Datei mit einem <symbol> pro Icon. Eingebunden per <use> braucht es kein Script, erbt currentColor und wird einmal geladen und gecacht. .ncss-icon-sprite (in helpers/icons.css) setzt Größe und Füllfarbe.

Per Kommandozeile

Reines Node-Skript ohne npm. Symbol-IDs sind die Phosphor-Dateinamen (house, heart-fill, star-duotone) - Stärke für alle per --weight, einzeln per name:stärke. Ein unbekannter Name liefert Vorschläge (home → house).

node tools/icons/sprite.mjs house bell heart:fill star:duotone arrow-right gear-six --out=icons.svg

<use href="datei.svg#id"> mit externer Datei funktioniert nur von derselben Herkunft (Origin) - das Sprite mit der Website ausliefern, nicht von einem fremden CDN.

Baukasten

Alle Phosphor-Icons durchsuchen (auch nach englischen Stichworten wie trash, calendar), anklicken, Stärke wählen, Sprite herunterladen. Das Verzeichnis (116 KB) wird erst geladen, wenn du hier ankommst.

Der Baukasten braucht JavaScript. Ohne JS: Icon-Namen auf phosphoricons.com nachschlagen und das Sprite mit dem Kommandozeilen-Aufruf oben bauen.

      Font Awesome als Alternative

      Font Awesome Free liegt selbst gehostet unter vendor/fontawesome/ (Webfont + SVGs, auch Grundlage von <wa-icon> in der Web-Awesome-Brücke). Kein Teil von ncss.css - nur einbinden, wenn das Projekt FA ohnehin nutzt. Komponenten wie .ncss-dialog-close stylen nur die Fläche, deshalb ist jedes Icon austauschbar:

      <link rel="stylesheet" href="vendor/fontawesome/css/fontawesome.min.css">
<link rel="stylesheet" href="vendor/fontawesome/css/solid.min.css">
<link rel="stylesheet" href="dist/integrations/fontawesome-font-display-fix.css">

<button class="ncss-dialog-close" aria-label="Schließen">
  <span class="ncss-icon ncss-icon-close" aria-hidden="true"></span>   <!-- Kern-Icon -->
  <i class="fa-solid fa-xmark" aria-hidden="true"></i>              <!-- oder Font Awesome -->
  <ncss-icon name="x"></ncss-icon>                               <!-- oder Phosphor -->
</button>

      integrations/fontawesome-font-display-fix.css setzt font-display: swap für die FA-Schriften (sonst bleiben Icons bis zum Laden unsichtbar).

      Icons barrierefrei einsetzen

      • Dekorativ oder bedeutungstragend? Steht Text daneben, ist das Icon Deko: aria-hidden="true" (bei <ncss-icon> automatisch). Trägt es allein Bedeutung (Status-Icon ohne Text), braucht es einen Namen: label="…" bzw. role="img" aria-label="…".
      • Buttons nur mit Icon brauchen aria-label am Button (nicht am Icon) - und ein Icon, das ohne JS sichtbar ist (Kern-Icon oder Sprite). Ein Tooltip ersetzt den Namen nicht.
      • Status nie nur über Farbe oder Icon: Warnung/Fehler zusätzlich in Worten.
      • Hochkontrastmodus (Windows forced-colors): Kern-Icons schalten auf die Systemfarbe CanvasText, <ncss-icon> und Sprites folgen über currentColor der erzwungenen Textfarbe - alle bleiben sichtbar.
      • Größe: Icons skalieren mit der Schrift, also auch mit Browser-Zoom und Textgröße. Klickflächen trotzdem mindestens 24×24 px (besser 44×44) - der Button gibt die Fläche vor, nicht das Icon.
      <!-- Deko: Text trägt die Bedeutung -->
<a href="/"><span class="ncss-icon ncss-icon-home" aria-hidden="true"></span> Startseite</a>

<!-- Nur Icon: Name am Button -->
<button class="ncss-btn ncss-btn--icon" aria-label="Löschen">
  <span class="ncss-icon ncss-icon-trash" aria-hidden="true"></span>
</button>

<!-- Icon trägt allein Bedeutung -->
<span class="ncss-icon ncss-icon-success" role="img" aria-label="Erledigt"></span>
