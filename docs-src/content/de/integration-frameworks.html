Integration in Frameworks

NativeCSS braucht keinen Bundler - wer ohnehin einen nutzt, kann es aber per npm importieren. Die Web Components (<ncss-…>) sind Light-DOM-Elemente ohne Abhängigkeiten und funktionieren in jedem Framework wie normales HTML.

Zwei Wege

Ohne Bundler

dist/ in den öffentlichen Ordner kopieren und per <link> einbinden - funktioniert mit jedem Server-Framework.

Mit Bundler (Vite, Astro …)

// npm i nativecss
import "nativecss";            // = dist/ncss.css
import "nativecss/theme.css";
import "nativecss/dist/js/tabs.js"; // nur benötigte Scripts

Laravel (Blade)

<!-- resources/views/layouts/app.blade.php, Dateien in public/ncss/ -->
<link rel="stylesheet" href="{{ asset('ncss/ncss.css') }}">
<link rel="stylesheet" href="{{ asset('ncss/theme.css') }}">

Wiederkehrendes Markup als Blade-Komponente kapseln - die Klassen bleiben NativeCSS:

<!-- resources/views/components/card.blade.php -->
<article {{ $attributes->merge(['class' => 'ncss-card ncss-border ncss-radius-lg']) }}>
  <div class="ncss-card-body ncss-stack">
    <h3>{{ $title }}</h3>
    {{ $slot }}
  </div>
</article>

<!-- Verwendung -->
<x-card title="Hallo">Inhalt</x-card>

Mit Vite: npm i nativecss und import "nativecss" in resources/js/app.js.

Symfony (Twig)

{# templates/base.html.twig, Dateien z. B. in assets/ncss/ (AssetMapper) #}
<link rel="stylesheet" href="{{ asset('ncss/ncss.css') }}">
<link rel="stylesheet" href="{{ asset('ncss/theme.css') }}">

Wiederkehrende Bausteine als Twig-Makros oder Twig-Komponenten (Symfony UX) - sie geben NativeCSS-Markup aus.

Astro, Eleventy, Hugo

  • Astro: import "nativecss"; im Layout-Frontmatter (oder Dateien in public/ + <link>); Komponenten-Scripts per <script src="…/dist/js/tabs.js"> nur in den Komponenten, die sie brauchen.
  • Eleventy / Hugo: dist/ per Passthrough-Copy (11ty) bzw. in static/ (Hugo) ausliefern, zwei <link>-Zeilen im Basis-Layout, Shortcodes/Partials geben NativeCSS-Markup aus.

React, Vue, Svelte

Die Web Components sind normale Custom Elements ohne Shadow DOM - Klassen, Tokens und theme.css greifen wie überall. Zwei Dinge beachten:

  • Events heißen ncss-<komponente>-<aktion> (z. B. ncss-compare-change). Am zuverlässigsten über eine Ref mit addEventListener abonnieren - das funktioniert in jedem Framework gleich.
  • Vue muss wissen, dass ncss-* keine Vue-Komponenten sind:
// vite.config.js
vue({ template: { compilerOptions: {
  isCustomElement: (tag) => tag.startsWith("ncss-")
} } })
// React: Event per Ref abonnieren
const ref = useRef(null);
useEffect(() => {
  const el = ref.current;
  const onChange = (e) => console.log(e.detail);
  el.addEventListener("ncss-compare-change", onChange);
  return () => el.removeEventListener("ncss-compare-change", onChange);
}, []);
return <ncss-compare ref={ref}>…</ncss-compare>;

Klassenbasierte Effekte mit Script (Count-up, Marquee …) brauchen nach dem Rendern neuer Inhalte das Event ncss-content-change - siehe Dynamische Inhalte. Custom Elements initialisieren sich selbst.

htmx und Alpine.js

Server-gerendertes HTML ist der natürliche Partner von NativeCSS. Für htmx genügt eine kleine Datei:

// assets/js/htmx-ncss.js
document.addEventListener("htmx:load", function (event) {
  document.dispatchEvent(new CustomEvent("ncss-content-change", {
    detail: { root: event.detail.elt }
  }));
});

Alpine.js steuert Zustände (z. B. x-show) - für Dialoge, Akkordeons und Tabs aber zuerst die nativen NativeCSS-Varianten (<dialog> + command, <details>, <ncss-tabs>) nutzen, die bringen Tastatur und ARIA schon mit.
