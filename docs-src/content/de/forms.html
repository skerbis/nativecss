Formulare

Native Elemente werden fertig gestylt (helpers/forms.css), keine JS-Nachbauten. Lebendes Beispiel: demo/forms.html.

Basis-Felder

KlasseZweck
.ncss-fieldLabel+Input+Hint als vertikale Gruppe
.ncss-label / --requiredFeld-Label, --required ergänzt ein rotes *
.ncss-input / .ncss-select / .ncss-textareaEinheitlicher Look, inkl. :user-invalid-Fehlerzustand
.ncss-field-hint / -errorHilfetext / Fehlertext unter einem Feld

Weitere Feldtypen (cross-browser gestylt)

TypBesonderheit
type="file"Größter Cross-Browser-Unterschied aller Feldtypen - ::file-selector-button (+ ::-webkit-file-upload-button für ältere Safari) bringt den Browser-Button auf .ncss-btn--secondary-Optik
type="color"Swatch-Fläche per ::-webkit-color-swatch(-wrapper)/::-moz-color-swatch an ncss-Radius angeglichen, feste Höhe passend zu den anderen Feldern
type="date/time/datetime-local/month/week"Kalender-/Uhr-Icon folgt automatisch dem Theme (color-scheme), keine eigene Anpassung nötig
type="search"appearance: none nötig, sonst rundet Safari das Feld eigenständig komplett ab
type="number"Native Spinner-Pfeile bewusst NICHT entfernt - echte Funktionalität, kein Grund sie zu kappen

Checkbox, Radio & Switch

.ncss-choiceCheckbox/Radio-Zeile - native Elemente, nur accent-color + Ausrichtung
.ncss-switchToggle-Switch aus <input type="checkbox">, per appearance:none neu gezeichnet, kein JS. role="switch" im Markup ergänzen
.ncss-rangeVereinheitlichtes <input type="range">, Track/Thumb angeglichen

Gruppierung & Rückmeldung

fieldset / legendOhne eigene Klasse zu Ende gestylt (wie <blockquote>) - ersetzt den nativen 3D-Rahmen
progress / meteraccent-color für die Grundfarbe. meter behält bewusst seine eigene Grün/Gelb/Rot-Bewertungslogik statt der Markenfarbe
outputHervorgehobene Darstellung für ein berechnetes Ergebnis

Buttons

.ncss-btn + --primary/--secondary/--danger. Jede Variante hat eine ECHTE :active-Rückmeldung (nicht nur :hover) - siehe Touch & mobile Viewports für die Begründung.
