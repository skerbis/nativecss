Screenreader & ARIA

Ein Screenreader liest nicht die Optik, sondern den Barrierefreiheitsbaum: Rolle, Name und Zustand jedes Elements. Sauberes HTML liefert das meiste davon - ARIA ergänzt nur, wo HTML keine Antwort hat.

Zugängliche Namen

Jedes Bedienelement braucht einen Namen, der sagt, was es tut (WCAG 4.1.2). Reihenfolge der Wahl:

  1. Sichtbarer Text - Button-Beschriftung, Linktext, <label for>. Am besten für alle, auch für Spracheingabe ("Klick auf Speichern"). Ist sichtbarer Text vorhanden, muss der zugängliche Name ihn enthalten (WCAG 2.5.3).
  2. .ncss-visually-hidden - zusätzlicher Text nur für Screenreader, z.B. in Icon-Buttons oder um "Mehr lesen" zu "Mehr lesen über Preise" zu ergänzen. Wird auch von Übersetzungs-Tools erfasst.
  3. aria-label - wenn kein Text ins Markup passt, z.B. am Schließen-Button .ncss-dialog-close mit &times;.
  4. aria-labelledby - verweist auf vorhandenen Text, z.B. einen Dialog auf seine Überschrift.

Das Icon selbst (.ncss-icon, <svg>) bekommt aria-hidden="true" - sonst liest der Screenreader im schlimmsten Fall einen Dateinamen oder gar nichts Sinnvolles vor. .ncss-btn--icon braucht immer einen Namen.

Ein Screenreader liest: "Suche öffnen, Taste" · "Link kopieren, Taste" · "Menü, Taste".

<!-- 1. Versteckter Text -->
<button type="button" class="ncss-btn ncss-btn--secondary ncss-btn--icon">
  <span class="ncss-icon ncss-icon-search" aria-hidden="true"></span>
  <span class="ncss-visually-hidden">Suche öffnen</span>
</button>

<!-- 2. aria-label -->
<button type="button" class="ncss-btn ncss-btn--secondary ncss-btn--icon" aria-label="Link kopieren">
  <span class="ncss-icon ncss-icon-copy" aria-hidden="true"></span>
</button>

<!-- 3. Am besten: sichtbarer Text -->
<button type="button" class="ncss-btn ncss-btn--secondary">
  <span class="ncss-icon ncss-icon-menu" aria-hidden="true"></span>
  Menü
</button>

Symbol-Tasten wie ⌘ in .ncss-kbd per <abbr title="Befehlstaste"> oder aria-label ausschreiben - das Zeichen allein wird oft gar nicht oder falsch vorgelesen.

Landmarks

Landmarks sind die Sprungmarken eines Screenreaders: <header> (banner), <nav> (navigation), <main> (main), <aside> (complementary), <footer> (contentinfo). Die HTML-Elemente bringen die Rolle mit - kein role="navigation" zusätzlich nötig.

  • Genau ein <main> pro Seite - zugleich das Ziel des Skip-Links.
  • Mehrere <nav> brauchen je ein aria-label, sonst hört man nur dreimal "Navigation". Das Wort "Navigation" nicht ins Label schreiben - der Screenreader sagt die Rolle selbst an.
  • <header>/<footer> zählen nur direkt unter <body> als Landmark, nicht innerhalb von <article> oder <section>.
  • Ein <section> wird erst mit zugänglichem Namen (aria-labelledby auf seine Überschrift) zur Region - für normale Abschnitte reicht eine Überschrift.
<body>
  <a href="#main" class="ncss-skip-link">Zum Inhalt springen</a>
  <header class="ncss-topbar">
    <nav class="ncss-nav" aria-label="Hauptmenü">...</nav>
  </header>
  <nav class="ncss-breadcrumb" aria-label="Brotkrumen">...</nav>
  <main id="main">
    <h1>Seitentitel</h1>
    ...
  </main>
  <footer>
    <nav aria-label="Rechtliches">...</nav>
  </footer>
</body>

Überschriften

Viele Screenreader-Nutzer navigieren zuerst über die Überschriften-Liste. Deshalb:

  • Eine <h1> pro Seite, darunter <h2>, <h3> ohne Ebenen zu überspringen.
  • Die Ebene richtet sich nach der Struktur, nicht nach der gewünschten Größe - die Optik regeln die Typografie-Klassen (siehe Typografie).
  • Fett gesetzter Text ist keine Überschrift, und eine Überschrift nicht für dekorative Zeilen missbrauchen. Ein Vorspann wie .ncss-eyebrow bleibt ein <p> neben der eigentlichen Überschrift.

Live-Regionen der Komponenten

Ändert sich Inhalt ohne Seitenwechsel, erfährt ein Screenreader davon nur über eine Live-Region (WCAG 4.1.3). Wichtig: die Region muss schon im DOM stehen, bevor Text hineingeschrieben wird - die ncss-Scripts legen sie deshalb gleich beim Start an.

Ein Screenreader liest den markierten Link als "Screenreader & ARIA, aktuelle Seite, Link". Die Hervorhebung hängt in ncss direkt am Attribut - kein zusätzliches .active nötig, Optik und Semantik können nicht auseinanderlaufen.

Kein ARIA ist besser als schlechtes ARIA

ARIA ändert nur, was der Screenreader ansagt - nie das Verhalten. Ein <div role="button"> wird dadurch weder fokussierbar noch per Enter auslösbar. Falsches ARIA ist schlimmer als keines, weil es Dinge verspricht, die nicht funktionieren.

  • Natives Element statt Rolle: <button> statt role="button", <dialog> statt role="dialog", <details> statt eigenem Akkordeon mit aria-expanded.
  • Keine redundanten Rollen (<nav role="navigation">, <button role="button">).
  • aria-hidden="true" nie auf fokussierbare Elemente - für ganze inaktive Bereiche inert verwenden (wie das Laufband für seine Kopie oder der Drilldown für die Wurzelliste).
  • Ein Zustand im ARIA muss immer zum sichtbaren Zustand passen - wer aria-expanded setzt, muss es beim Schließen auch zurücksetzen.
  • Eine Liste mit list-style: none verliert in VoiceOver/Safari ihre Listen-Semantik - ncss setzt eigene Marker deshalb nur zusammen mit role="list" im Markup.
  • Reine Grafiken wie .ncss-sparkline bleiben aria-hidden; die echten Werte stehen daneben in einer .ncss-visually-hidden-Tabelle.
