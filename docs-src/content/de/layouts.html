Sektionen

Drei Bausteine für typische Marketing-/Landingpage-Sektionen: .ncss-split (Text neben Bild), .ncss-tile (volle-Breite Farbflächen, bekannt aus UIkit) und .ncss-accordion-split (transformierendes Akkordeon, bekannt von apple.com). Split und Tile lassen sich kombinieren - eine Tile als Hintergrundfläche, darin ein Split-Layout.

1. Split: Grundstruktur

.ncss-split-container erzeugt den Container-Query-Kontext (ein Element kann per Spec nicht seine eigene Breite abfragen, siehe Karten, Abschnitt 6 für dieselbe Einschränkung), .ncss-split ist das eigentliche zweispaltige Layout. Ab 36rem CONTAINER-Breite stehen Media und Content nebeneinander, darunter stapeln sie sich automatisch.

<div class="ncss-split-container">
  <div class="ncss-split">
    <div class="ncss-split-media"><img src="foto.jpg" alt="..."></div>
    <div class="ncss-split-content">
      <h3>Titel</h3>
      <p>Text ...</p>
    </div>
  </div>
</div>

Grundbeispiel

Fenster/Panel schmaler ziehen, um das Stapeln unter 36rem zu sehen.

2. Bild links vs. rechts

Kein Modifier nötig - reine Dokumentreihenfolge, genau wie bei Karten (.ncss-card-media oben/unten). .ncss-split-media als ERSTES Kind = links (und beim Stapeln oben), als LETZTES Kind = rechts (und beim Stapeln unten). Kein row-reverse-Trick, der die Vorlese-/Fokus-Reihenfolge vom visuellen Layout entkoppeln würde.

<!-- Bild rechts: .ncss-split-media einfach als LETZTES Kind -->
<div class="ncss-split">
  <div class="ncss-split-content">...</div>
  <div class="ncss-split-media">...</div>
</div>

Bild rechts

Dieselbe Klasse, nur die Kindreihenfolge im Markup ist getauscht.

3. Vertikale Ausrichtung & Breiten-Verhältnis

--ncss-split-align (Default center) steuert, wie die beiden Spalten zueinander ausgerichtet sind, sobald sie nebeneinander stehen - kein Effekt im gestapelten Zustand. Bequemlichkeits-Klassen für die häufigsten Werte:

KlasseWirkung
.ncss-split--align-startBeide Spalten oben ausgerichtet
.ncss-split--align-endBeide Spalten unten ausgerichtet
.ncss-split--align-stretchBeide Spalten gleich hoch gestreckt

Für ein asymmetrisches Breiten-Verhältnis (statt 50/50) --ncss-split-media-width direkt auf .ncss-split-media setzen - die Content-Spalte füllt automatisch den Rest, ergibt immer zusammen 100%:

<div class="ncss-split ncss-split--align-start">
  <div class="ncss-split-media" style="--ncss-split-media-width: 40%;">...</div>
  <div class="ncss-split-content">...</div>
</div>

40/60-Aufteilung, oben ausgerichtet

Media schmaler als die Content-Spalte, beide oben bündig statt zentriert.

4. Tile: Farbflächen-Sektionen

Bekannt aus UIkit (uk-tile-default/-muted/-primary/-secondary) - volle-Breite Blöcke zum Gliedern einer langen Seite in klar unterscheidbare Abschnitte. .ncss-tile allein (ohne Modifier) ist die normale Seitenfläche, kein sichtbarer Unterschied zur Umgebung außer dem eigenen Innenabstand.

KlasseEntspricht UIkitWirkung
.ncss-tileuk-tile-defaultNormale Seitenfläche
.ncss-tile--muteduk-tile-muted--ncss-color-bg-subtle als Hintergrund
.ncss-tile--branduk-tile-primaryMarkenfarbe, Text kippt automatisch auf hell
.ncss-tile--brand-2uk-tile-secondaryZweitfarbe, Text kippt automatisch auf hell
 
<section class="ncss-tile ncss-tile--brand">
  <h2>Titel</h2>
  <p>Text ...</p>
</section>

Marken-Fläche (--brand)

Heller Text automatisch, keine eigene Klasse nötig.

Zweitfarben-Fläche (--brand-2)

Dieselbe automatische Textumschaltung, andere Markenfarbe.

5. Weiße Flächen innerhalb einer Tile

Der automatische helle Text von --brand/--brand-2 ist eine reine Nachfahren-Selektor-Vererbung - ohne Gegenmaßnahme würde er auch in eine verschachtelte weiße .ncss-card hineinlaufen und dort unlesbar werden (derselbe Fallstrick, der zuerst an product.html gefunden wurde, hier von vornherein generisch mitgelöst). .ncss-tile setzt .ncss-card und <pre> DARIN deshalb automatisch auf den normalen dunklen Text zurück:

Marken-Fläche mit Karte

Dieser Text ist hell.

Karten-Titel

Dieser Text bleibt normal dunkel-auf-weiß, unabhängig von der Tile-Farbe.

6. Kombiniert: Split innerhalb einer Tile

Beide Bausteine sind bewusst unabhängig voneinander - eine Tile als Hintergrundfläche, darin ganz normal ein Split-Layout. Ohne weiteres Zutun bleibt eine Tile innerhalb ihres umgebenden Containers - für volle Bildschirmbreite bis zum Bildschirmrand zusätzlich .ncss-full-bleed auf die Tile kombinieren, das bleibt bewusst eine separate Entscheidung.

<section class="ncss-tile ncss-tile--muted ncss-full-bleed">
  <div class="ncss-container">
    <div class="ncss-split-container">
      <div class="ncss-split">
        <div class="ncss-split-media">...</div>
        <div class="ncss-split-content">...</div>
      </div>
    </div>
  </div>
</section>

Split in einer Tile

Zwei unabhängige Bausteine, frei kombinierbar.

7. Transformierendes Akkordeon

Bekannt von apple.com - ein Text-Akkordeon, dessen zugehöriges Bild rechts automatisch mit dem gerade geöffneten Punkt wechselt. Komplett nativ, KEIN JavaScript: exklusives Öffnen/Schließen über <details name="..."> (Baseline seit September 2025), das passende Bild wird per :has() ausgewählt - dieselbe Technik, die schon pre:has(> code[class*="language-"]) in den Code-Blöcken auf dieser Seite nutzt.

Container Queries

Komponenten reagieren auf ihren eigenen Platz, nicht auf den Viewport.

Cascade Layers

Reihenfolge statt Spezifitäts-Kämpfe - kein !important nötig.

light-dark()

Ein Wert pro Token deckt Hell und Dunkel ab - kein zweites Stylesheet.

<div class="ncss-accordion-split-container">
  <div class="ncss-accordion-split">
    <div class="ncss-accordion-split-list">
      <details name="mein-akkordeon" class="ncss-accordion-split-item" open>
        <summary>Punkt eins</summary>
        <div class="ncss-accordion-split-body">
          <p>Text ...</p>
          <!-- fürs Stapeln auf Mobile, dasselbe Bild wie unten -->
          <div class="ncss-accordion-split-media-mobile"><img src="bild-1.jpg" alt="..."></div>
        </div>
      </details>
      <!-- weitere Punkte, immer dasselbe name="..." -->
    </div>
    <div class="ncss-accordion-split-media">
      <img src="bild-1.jpg" alt="...">
      <!-- ein Bild pro Punkt, gleiche Reihenfolge -->
    </div>
  </div>
</div>

name="..." muss pro Akkordeon-Instanz auf der Seite eindeutig sein (wie eine Radio-Button-Gruppe), sonst gruppieren sich mehrere Akkordeons ungewollt miteinander. Jedes Bild steht bewusst ZWEIMAL im Markup (Desktop-Spalte + mobile Inline-Kopie) - ohne JS lässt sich ein DOM-Knoten nicht zwischen zwei entfernten Containern verschieben. Dieselbe Bild-URL wird trotzdem nur einmal geladen (normales HTTP-Caching), pro Breakpoint ist immer nur eine der beiden Kopien im Layout. Unterstützt bis zu 6 Punkte (mehr wären für dieses Muster ohnehin unüblich).
