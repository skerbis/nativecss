Basis-Komponenten

Die native Alternative zu <wa-tab-group>, <wa-tooltip> und <wa-callout>: kein ES-Modul, kein Shadow DOM, das Markup bleibt normales HTML, das auch ohne JavaScript funktioniert. Jede Datei läuft allein mit colors.css, tokens.css, reset.css und base.css. Web Awesome bleibt optional (siehe Web Awesome).

Einbindung

In ncss.css enthalten. Einzeln (Cherry-Picking):

<link rel="stylesheet" href="ncss/components/tabs.css">        <!-- je im Layer components -->
<link rel="stylesheet" href="ncss/components/tooltip.css">
<link rel="stylesheet" href="ncss/components/pagination.css">  <!-- reines CSS -->
<link rel="stylesheet" href="ncss/components/alert.css">       <!-- reines CSS -->

Alle Scripts sind eigenständig und funktionieren auch mit nachgeladenem Markup (htmx, fetch, REDAXO-Frontend-Editing): Tabs als Custom Element über connectedCallback, Tooltip und Dismiss über Ereignis-Delegation - siehe Dynamische Inhalte.

Tooltip

Kurzer Text-Hinweis zu einem Bedienelement (WAI-ARIA-APG "Tooltip"), als natives popover="hint" mit interestfor: in Chromium erledigt der Browser Hover, Fokus, Verzögerung und Esc ganz ohne JS; js/tooltip.js liefert dasselbe Verhalten in anderen Browsern. Positionierung per CSS Anchor Positioning, sonst rechnet das Script. Für Links, Bilder oder Profile im Overlay stattdessen die Hovercard - ein Tooltip enthält nie etwas Anklickbares.

Klick auf die abgedunkelte Fläche, Esc oder der Button schließen. Text darin lässt sich markieren, ohne dass der Dialog zugeht.

Langes Formular

Hier schließt nur der Button - weder Klick daneben noch Esc verwerfen versehentlich Eingaben.

Geschlossen wird über requestClose(): das cancel-Event feuert vorher, event.preventDefault() hält den Dialog offen (z. B. "Ungespeicherte Änderungen verwerfen?"). Eine Textmarkierung, die im Panel beginnt und daneben endet, schließt nicht. Einbindung: <script src="ncss/js/dialog-light-dismiss.js" defer></script>.

Barrierefreiheit

Tastatur

TasteAktion
EscSchließt (außer bei closedby="none").
TabBleibt im offenen Modal gefangen (nativer Top-Layer-Dialog), der Rest der Seite ist inert.
Enter / LeertasteAuf dem Schließen-Button: schließt. Der Fokus geht danach an den Button zurück, der den Dialog geöffnet hat.

Screenreader

<dialog> per showModal()/command="show-modal" ist ein modaler Dialog mit Namen aus aria-labelledby. Klick daneben ist eine reine Maus-/Touch-Abkürzung - jeder Dialog braucht trotzdem einen sichtbaren Schließen-Button (aria-label).

Einstellungen

Ein- und Ausblenden folgen der Modal-Animation, bei reduzierter Bewegung sofort. Der Backdrop bleibt auch im Hochkontrastmodus als Fläche klickbar. Bei Zoom scrollt das Panel in sich.

Ohne JS

Öffnen per command braucht in alten Browsern js/command-fallback.js. Ohne dialog-light-dismiss.js gilt das, was im Markup steht: ohne closedby schließen nur Esc und Buttons.
