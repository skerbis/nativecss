Basis-Komponenten

Die native Alternative zu <wa-tab-group>, <wa-tooltip> und <wa-callout>: kein ES-Modul, kein Shadow DOM, das Markup bleibt normales HTML, das auch ohne JavaScript funktioniert. Jede Datei läuft allein mit colors.css, tokens.css, reset.css und base.css. Web Awesome bleibt optional (siehe Web Awesome).

Einbindung

In ncss.css enthalten. Einzeln (Cherry-Picking):

<link rel="stylesheet" href="ncss/components/tabs.css">        <!-- je im Layer components -->
<link rel="stylesheet" href="ncss/components/tooltip.css">
<link rel="stylesheet" href="ncss/components/pagination.css">  <!-- reines CSS -->
<link rel="stylesheet" href="ncss/components/alert.css">       <!-- reines CSS -->
<script src="ncss/js/tabs.js" defer></script>      <!-- <ncss-tabs> -->
<script src="ncss/js/tooltip.js" defer></script>   <!-- Fallback ohne interestfor -->
<script src="ncss/js/dismiss.js" defer></script>   <!-- Schließen-Buttons -->
<script src="ncss/js/dialog-light-dismiss.js" defer></script>  <!-- Klick daneben schließt -->

Alle Scripts sind eigenständig und funktionieren auch mit nachgeladenem Markup (htmx, fetch, REDAXO-Frontend-Editing): Tabs als Custom Element über connectedCallback, Tooltip und Dismiss über Ereignis-Delegation - siehe Dynamische Inhalte.

Tabs

<ncss-tabs> folgt dem WAI-ARIA-APG-Muster "Tabs". Ausgangspunkt ist eine Sprungmarken-Liste über Abschnitten - ohne JavaScript bleibt genau das stehen (alle Inhalte sichtbar, jeder Link springt zu seinem Abschnitt). Mit js/tabs.js werden daraus Tabs mit Rollen, Roving-Tabindex und Pfeiltasten. hash spiegelt den aktiven Tab in der Adresse (teilbar, z. B. #tab-technik).

<ncss-tabs class="ncss-tabs" hash>
  <div class="ncss-tabs-list" aria-label="Produktinfos">
    <a href="#tab-beschreibung">Beschreibung</a>
    <a href="#tab-technik">Technische Daten</a>
    <a href="#tab-lieferung">Lieferung</a>
  </div>
  <section class="ncss-tabs-panel" id="tab-beschreibung">
    <h3 class="ncss-tabs-heading">Beschreibung</h3>
    <p>Handgefertigte Leuchte aus Eichenholz, gedimmt per Drehregler.</p>
  </section>
  <section class="ncss-tabs-panel" id="tab-technik">
    <h3 class="ncss-tabs-heading">Technische Daten</h3>
    <p>LED, 2700 K, 9 W, Kabel 2 m, Höhe 38 cm.</p>
  </section>
  <section class="ncss-tabs-panel" id="tab-lieferung">
    <h3 class="ncss-tabs-heading">Lieferung</h3>
    <p>Versand innerhalb von 3 Werktagen, Rückgabe 30 Tage.</p>
  </section>
</ncss-tabs>

Screenreader

Liste role="tablist" mit Namen aus aria-label, je Tab role="tab" + aria-selected + aria-controls, Panel role="tabpanel" mit aria-labelledby. Screenreader sagen z. B. "Technische Daten, Tab, ausgewählt, 2 von 3". Vertikal zusätzlich aria-orientation="vertical".

Einstellungen

Keine Animation beim Wechsel (nichts für reduzierte Bewegung abzuschalten). Aktiver Tab hat neben der Farbe einen 3px-Unterstrich, im Hochkontrastmodus eine Highlight-Kontur. Bei Zoom scrollt die Tab-Leiste horizontal in sich, die Seite nicht.

Ohne JS

Sprungmarken-Liste + alle Abschnitte untereinander, die Überschriften .ncss-tabs-heading gliedern die Seite. Mit JS werden sie nur optisch ausgeblendet.

Tooltip

Kurzer Text-Hinweis zu einem Bedienelement (WAI-ARIA-APG "Tooltip"), als natives popover="hint" mit interestfor: in Chromium erledigt der Browser Hover, Fokus, Verzögerung und Esc ganz ohne JS; js/tooltip.js liefert dasselbe Verhalten in anderen Browsern. Positionierung per CSS Anchor Positioning, sonst rechnet das Script. Für Links, Bilder oder Profile im Overlay stattdessen die Hovercard - ein Tooltip enthält nie etwas Anklickbares.

<div class="ncss-cluster">
  <button type="button" class="ncss-btn ncss-btn--primary" interestfor="tip-save" aria-describedby="tip-save">Speichern</button>
  <span class="ncss-tooltip" id="tip-save" popover="hint" role="tooltip">Tastenkürzel: Strg + S</span>

  <button type="button" class="ncss-btn ncss-btn--secondary ncss-btn--icon" aria-label="Kopieren" interestfor="tip-copy" aria-describedby="tip-copy">
    <span class="ncss-icon ncss-icon-copy" aria-hidden="true"></span>
  </button>
  <span class="ncss-tooltip" id="tip-copy" popover="hint" role="tooltip">Link in die Zwischenablage kopieren</span>
</div>

Wichtig: der Tooltip ist eine Beschreibung, nie der Name. Der Icon-Button oben heißt per aria-label "Kopieren"; ohne JS und ohne interestfor bleibt der Tooltip unsichtbar, die Beschreibung kommt über aria-describedby trotzdem an.

Pagination

Barrierefreiheit

Tastatur

TasteAktion
TabErreicht Links/Buttons im Hinweis und den Schließen-Button.
Enter / LeertasteSchließt den Hinweis. Der Fokus springt auf den nächsten schließbaren Hinweis, sonst auf den umgebenden Bereich - nie ins Leere.

Screenreader

Statische Hinweise beim Laden bekommen keine Rolle (werden normal gelesen). Erst später eingefügt: role="alert" für dringende Fehler (sofortige Ansage), role="status" für Bestätigungen (höfliche Ansage). Schließen-Button mit aria-label.

Einstellungen

Keine Animation. Text in der -on-soft-Stufe der Familie (Kontrast ≥ 4,5:1 hell und dunkel). Im Hochkontrastmodus Rahmen statt Fläche, Symbole in CanvasText. Fließt bei Zoom frei um.

Ohne JS

Hinweise funktionieren voll. Nur der Schließen-Button braucht JS - mit hidden im Markup erscheint er erst, wenn er auch funktioniert.

Dialoge: Klick daneben schließt

Modal, Off-Canvas, Befehlspalette und Lightbox schließen per Klick auf die abgedunkelte Fläche - nativ über <dialog closedby="any">. js/dialog-light-dismiss.js macht das zum Default (setzt closedby="any" an jedem ncss-Dialog ohne eigenes Attribut, auch an später eingefügten und per JS geöffneten) und emuliert es in Browsern ohne closedby. Abschalten pro Dialog mit dem nativen Attribut: closedby="closerequest" (nur Esc + Buttons) oder closedby="none" (nur Buttons, z. B. lange Formulare).

<div class="ncss-cluster">
  <button type="button" class="ncss-btn ncss-btn--primary" command="show-modal" commandfor="ld-demo">Modal öffnen</button>
  <button type="button" class="ncss-btn ncss-btn--secondary" command="show-modal" commandfor="ld-form">Formular (closedby="none")</button>
</div>
<dialog id="ld-demo" class="ncss-modal" aria-labelledby="ld-demo-title">
  <button type="button" class="ncss-dialog-close" command="close" commandfor="ld-demo" aria-label="Schließen">&times;</button>
  <div class="ncss-modal-header"><h3 id="ld-demo-title">Klick daneben schließt</h3></div>
  <div class="ncss-modal-body"><p>Klick auf die abgedunkelte Fläche, Esc oder der Button schließen. Text darin lässt sich markieren, ohne dass der Dialog zugeht.</p></div>
</dialog>
<dialog id="ld-form" class="ncss-modal" closedby="none" aria-labelledby="ld-form-title">
  <div class="ncss-modal-header"><h3 id="ld-form-title">Langes Formular</h3></div>
  <div class="ncss-modal-body"><p>Hier schließt nur der Button - weder Klick daneben noch Esc verwerfen versehentlich Eingaben.</p></div>
  <div class="ncss-modal-footer"><button type="button" class="ncss-btn ncss-btn--primary" command="close" commandfor="ld-form">Fertig</button></div>
</dialog>

Klick daneben schließt

Klick auf die abgedunkelte Fläche, Esc oder der Button schließen. Text darin lässt sich markieren, ohne dass der Dialog zugeht.

Langes Formular

Hier schließt nur der Button - weder Klick daneben noch Esc verwerfen versehentlich Eingaben.

Geschlossen wird über requestClose(): das cancel-Event feuert vorher, event.preventDefault() hält den Dialog offen (z. B. "Ungespeicherte Änderungen verwerfen?"). Eine Textmarkierung, die im Panel beginnt und daneben endet, schließt nicht. Einbindung: <script src="ncss/js/dialog-light-dismiss.js" defer></script>.

Barrierefreiheit

Tastatur

TasteAktion
EscSchließt (außer bei closedby="none").
TabBleibt im offenen Modal gefangen (nativer Top-Layer-Dialog), der Rest der Seite ist inert.
Enter / LeertasteAuf dem Schließen-Button: schließt. Der Fokus geht danach an den Button zurück, der den Dialog geöffnet hat.

Screenreader

<dialog> per showModal()/command="show-modal" ist ein modaler Dialog mit Namen aus aria-labelledby. Klick daneben ist eine reine Maus-/Touch-Abkürzung - jeder Dialog braucht trotzdem einen sichtbaren Schließen-Button (aria-label).

Einstellungen

Ein- und Ausblenden folgen der Modal-Animation, bei reduzierter Bewegung sofort. Der Backdrop bleibt auch im Hochkontrastmodus als Fläche klickbar. Bei Zoom scrollt das Panel in sich.

Ohne JS

Öffnen per command braucht in alten Browsern js/command-fallback.js. Ohne dialog-light-dismiss.js gilt das, was im Markup steht: ohne closedby schließen nur Esc und Buttons.
