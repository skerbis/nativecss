Nutzer-Einstellungen

Betriebssysteme und Browser kennen Einstellungen für weniger Bewegung, mehr Kontrast, weniger Transparenz, eigene Systemfarben und Hell/Dunkel. CSS kann sie per Media Query abfragen - ncss tut das an zentraler Stelle und in den Komponenten, wo es nötig ist.

Einstellungen ausprobieren

Die Kontrollkästchen simulieren die jeweilige Einstellung nur auf der Beispiel-Fläche. Die echten Einstellungen finden sich z.B. unter macOS in "Bedienungshilfen > Anzeige", unter Windows in "Barrierefreiheit" bzw. "Kontrastdesigns"; in den Entwicklerwerkzeugen von Chrome/Edge lassen sie sich unter "Rendering" emulieren.

Reduzierte Bewegung: prefers-reduced-motion

Große Bewegungen, Parallax und Zoom können Schwindel und Übelkeit auslösen (WCAG 2.3.3). reset.css deckelt deshalb global alle Animationen und Übergänge auf praktisch null und schaltet weiches Scrollen ab - keine Komponente muss das einzeln prüfen. ::details-content ist eigens aufgeführt, weil der Universalselektor dieses Pseudo-Element nicht erreicht.

/* reset.css */
@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after, *::details-content {
    animation-duration: 0.01ms !important;
    animation-iteration-count: 1 !important;
    transition-duration: 0.01ms !important;
    scroll-behavior: auto !important;
  }
}

Wo die globale Regel nicht reicht, regeln die Komponenten selbst nach:

  • Laufband .ncss-marquee - die Animation startet nur unter no-preference; mit reduzierter Bewegung wird die Reihe ein normal seitlich scrollbarer Bereich, die Kopie verschwindet.
  • Scripts prüfen matchMedia("(prefers-reduced-motion: reduce)"): js/backdrop.js wechselt keine Bilder automatisch, js/count-up.js zeigt sofort die fertige Zahl, js/view-transitions.js verzichtet auf Übergänge, js/video-card.js spielt keine Vorschau ab.
  • Hintergrund-Video - CSS kann <video autoplay> nicht anhalten. js/hero-video-motion.js entfernt deshalb bei reduzierter Bewegung das autoplay und pausiert das Video; das Poster bleibt sichtbar.
  • Hell/Dunkel-Wechsel - die weiche Überblendung beim Umschalten läuft nur unter no-preference.

Für eigene Effekte: Bewegung als Zusatz formulieren, nicht als Ausgangszustand. Dann ist der Fall "keine Bewegung" automatisch der stabile.

.mein-teaser {
  opacity: 1;
}
@media (prefers-reduced-motion: no-preference) {
  .mein-teaser {
    animation: einblenden 600ms ease-out both;
  }
}
<!-- Nur auf Seiten mit Hintergrund-Video im Hero -->
<script src="dist/js/hero-video-motion.js" defer></script>

Unabhängig von der Einstellung: Alles, was sich länger als 5 Sekunden automatisch bewegt, braucht eine Pause-Möglichkeit (WCAG 2.2.2) - beim Laufband per [data-ncss-marquee-toggle], siehe Medien.

Mehr Kontrast: prefers-contrast

Die ncss-Farbtokens sind bereits auf AA-Kontrast kalibriert (siehe Farben & Flächen), deshalb gibt es keine globale Sonderregel. prefers-contrast: more nutzt der Videoplayer: dunklerer Verlauf hinter der Steuerleiste, deutlichere Zeitleiste über bewegtem Bild.

Für eigene Gestaltung lohnt die Abfrage überall, wo bewusst zurückhaltend gestaltet wurde - gedämpfte Hilfetexte, feine Rahmen, Text auf Bildern:

@media (prefers-contrast: more) {
  .mein-bereich {
    --ncss-color-text-muted: var(--ncss-color-text);
    --ncss-color-border: currentColor;
  }
}

Weniger Transparenz: prefers-reduced-transparency

Milchglas-Flächen (backdrop-filter) und halbtransparente Hintergründe erschweren das Lesen, weil der Untergrund durchscheint. Unter prefers-reduced-transparency: reduce bekommen in ncss die Einblendung im Videoplayer und die Bildunterschrift von <ncss-scroll-video> eine deckende Fläche.

.meine-glasleiste {
  background-color: color-mix(in oklch, var(--ncss-color-surface) 60%, transparent);
  backdrop-filter: blur(8px);
}
@media (prefers-reduced-transparency: reduce) {
  .meine-glasleiste {
    background-color: var(--ncss-color-surface);
    backdrop-filter: none;
  }
}

Systemfarben: forced-colors

Im Windows-Kontrastmodus (und vergleichbaren Modi) ersetzt der Browser alle Farben durch eine kleine Palette von Systemfarben, Hintergrundbilder und Schatten verschwinden. Was nur über Farbe, Schatten oder background-color sichtbar war, ist dann weg. ncss fängt das in vielen Komponenten mit @media (forced-colors: active) ab, u.a. Icons, Badges, Tags, Toasts, Befehlspalette, Abschnitts-Navigation, Spinner, Vorher/Nachher, Segmentierte Auswahl und die Mediaplayer.

Beispiel Icons: .ncss-icon ist eine per mask-image ausgestanzte Fläche mit background-color: currentColor - im Kontrastmodus war sie leer. Die Lösung:

@media (forced-colors: active) {
  .ncss-icon {
    forced-color-adjust: none;
    background-color: CanvasText;
  }
}

Faustregeln für eigene Komponenten:

  • Zustände nie nur über Hintergrundfarbe zeigen - ein Rahmen (auch transparent) wird im Kontrastmodus sichtbar.
  • Systemfarben-Schlüsselwörter verwenden: Canvas, CanvasText, LinkText, ButtonText, Highlight, GrayText.
  • forced-color-adjust: none nur gezielt einsetzen und dann selbst Systemfarben setzen - nie, um die Einstellung auszuhebeln.
  • Der :focus-visible-Ring nutzt outline und bleibt damit auch im Kontrastmodus sichtbar.

Hell und dunkel: prefers-color-scheme und light-dark()

Alle Farbtokens in colors.css sind mit light-dark() definiert und folgen über color-scheme: light dark automatisch der System-Einstellung. data-theme="light" oder "dark" am <html> überschreibt sie; .ncss-scheme-dark/-light stellt einzelne Bereiche um. Beide Paletten sind auf Kontrast geprüft - eigene Farben müssen in beiden Modi bestehen.

:root {
  color-scheme: light dark;
  --ncss-color-text: light-dark(#1a1a1a, #f0f0f0);
  --ncss-color-focus-ring: light-dark(#0057d8, #6ea8ff);
}
:root[data-theme="dark"] {
  color-scheme: dark;
}

Ein Umschalter ist optional: js/theme-toggle.js speichert die Wahl, folgt ohne Wahl live dem System, setzt aria-pressed und ein wechselndes aria-label, das sagt, was der Klick bewirkt ("Dunkles Design einschalten"). js/theme-toggle-early.js im <head> verhindert das kurze Aufblitzen des falschen Modus.

<head>
  <script src="dist/js/theme-toggle-early.js"></script>
  <link rel="stylesheet" href="dist/ncss.css">
  <script src="dist/js/theme-toggle.js" defer></script>
</head>
...
<button type="button" class="ncss-theme-toggle" data-ncss-theme-toggle>
  <span class="ncss-icon ncss-icon-moon ncss-theme-icon-dark" aria-hidden="true"></span>
  <span class="ncss-icon ncss-icon-sun ncss-theme-icon-light" aria-hidden="true"></span>
</button>

Die Variante data-ncss-theme-toggle="cycle" wechselt reihum zwischen System, Hell und Dunkel und zeigt den aktuellen Namen in einem Kind-Element [data-ncss-theme-label].
