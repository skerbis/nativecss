Integration in CMS

NativeCSS ist reines CSS plus einzelne, optionale Scripts - jedes CMS, das eine <link>-Zeile ausgeben kann, kann NativeCSS nutzen. Diese Seite zeigt den jeweils üblichen Weg, eigene Markenwerte über theme.css zu setzen und nur das zu laden, was eine Seite braucht.

Das Grundmuster (gilt überall)

  1. Dateien holen: Release-ZIP von GitHub (nur dist/), CDN oder npm i @skerbis/nativecss - siehe Schnellstart.
  2. Einbinden: ncss.css (alles) oder eine ausgedünnte Kopie mit nur den benötigten @import-Zeilen, danach theme.css für eigene Werte.
  3. Scripts nur bei Bedarf: jede Komponente mit Verhalten hat genau eine Datei in dist/js/ - nur einbinden, wo die Komponente vorkommt. Der Code-Inspektor (unten rechts) zeigt für jedes Element, welche Datei es braucht.
  4. Nachgeladene Inhalte (Frontend-Editing, AJAX, htmx): nach dem Einfügen ncss-content-change feuern - siehe Dynamische Inhalte.
<link rel="stylesheet" href="/assets/ncss/ncss.css">
<link rel="stylesheet" href="/assets/ncss/theme.css">
<!-- nur auf Seiten mit Dialogen, Tabs, Playern … -->
<script src="/assets/ncss/js/dialog-light-dismiss.js" defer></script>

Design-Einstellungen eines CMS (Farbe, Schrift, Radius aus einem Backend-Formular) passen ideal auf die Seed-Werte in theme.css: das CMS schreibt nur eine kleine unlayered Datei bzw. einen <style>-Block mit --ncss-…-Werten auf :root, alle abgeleiteten Stufen rechnet NativeCSS selbst - siehe Theme anpassen.

REDAXO 6 + fluid

Das AddOn fluid bringt ein fertiges NativeCSS-Kit mit: unter Website → Kit → NativeCSS umschalten, die Inhalte bleiben. Redakteure bearbeiten direkt auf der Seite (Blöcke, Design-Vorlagen, Farben, Schriften), das Kit lädt pro Seite nur die CSS-/JS-Dateien der verwendeten Blöcke.

  • Blöcke mit NativeCSS-Komponenten: „Video & Audio“ (<ncss-video-player> mit Kapiteln und Untertiteln, <ncss-audio-player> mit Playlist), „Vorher/Nachher“ (<ncss-compare>), Kennzahlen mit Count-up, Logos als Laufband, Scrollytelling, Hintergrundvideo im Hero.
  • Einblend-Effekt als Einstellung am Abschnitt (Keiner · Sanft einblenden · Von unten · Kreis · Vorhang) - Standard „Keiner“, bei reduzierter Bewegung automatisch aus.
  • Aktualisieren auf eine neue NativeCSS-Version: php bin/console fluid:kit:ncss-update --tag=v1.1.0 (oder --from=/pfad/zu/nativecss), zeigt neue/geänderte Dateien und vermerkt die Version.

REDAXO 5 (klassisch)

dist/ z. B. nach assets/ncss/ (oder in den Assets-Ordner eines Projekt-/Theme-AddOns) kopieren und im Template einbinden:

<link rel="stylesheet" href="<?= rex_url::base('assets/ncss/ncss.css') ?>">
<link rel="stylesheet" href="<?= rex_url::base('assets/ncss/theme.css') ?>">
  • Module geben ganz normales NativeCSS-Markup aus (Karte, Akkordeon mit <details>, Dialog …) - keine Wrapper-Klassen nötig.
  • Bestehende UIkit-Module lassen sich mit dem UIkit→NativeCSS-Konverter umstellen; PHP im Modul-Code bleibt dabei unangetastet (Kommandozeile: node tools/uikit-to-ncss/convert.mjs modules/ --write).
  • Theme-Werte aus der Datenbank (z. B. Design-Einstellungen eines Theme-AddOns): im Template einen kleinen <style>:root{--ncss-color-brand: …}</style>-Block NACH den beiden Dateien ausgeben.

WordPress

Im (Child-)Theme die Dateien nach ncss/ legen und in der functions.php einbinden - für Frontend und Block-Editor:

add_action('wp_enqueue_scripts', function () {
    wp_enqueue_style('nativecss', get_theme_file_uri('ncss/ncss.css'), [], '1.1.0');
    wp_enqueue_style('nativecss-theme', get_theme_file_uri('ncss/theme.css'), ['nativecss'], '1.1.0');
});

// gleiche Optik im Block-Editor
add_action('after_setup_theme', function () {
    add_theme_support('editor-styles');
    add_editor_style(['ncss/ncss.css', 'ncss/theme.css']);
});
  • theme.json: die Farbpalette auf NativeCSS-Tokens zeigen lassen ("color": "var(--ncss-color-brand)"), damit Editor-Farbwahl und NativeCSS-Theme dieselbe Quelle haben.
  • Block-Styles/Patterns: eigene Block-Stile können einfach NativeCSS-Klassen setzen (z. B. ncss-card), Patterns liefern fertiges NativeCSS-Markup.

TYPO3

Im Sitepackage unter Resources/Public/ncss/ ablegen und im Fluid-Seitentemplate laden:

<f:asset.css identifier="nativecss" href="EXT:sitepackage/Resources/Public/ncss/ncss.css" />
<f:asset.css identifier="nativecss-theme" href="EXT:sitepackage/Resources/Public/ncss/theme.css" />

Content-Element-Templates (Fluid) geben NativeCSS-Markup aus; Scripts einzelner Komponenten per <f:asset.script> nur in den Templates, die sie brauchen.

Contao, Kirby und andere

  • Contao: dist/ in den Theme-Ordner unter files/, im Seitenlayout als externe Stylesheets eintragen oder im eigenen Seiten-Template ausgeben; Inhaltselement-Templates liefern NativeCSS-Markup.
  • Kirby: <?= css(['assets/ncss/ncss.css', 'assets/ncss/theme.css']) ?> im Header-Snippet; Blocks/Snippets geben NativeCSS-Markup aus.
  • Statamic, Craft, Joomla, Drupal …: dasselbe Muster - zwei <link>-Zeilen im Layout, Markup in den Komponenten-Templates, Scripts nur dort, wo nötig.
