Art Direction: <picture><source media="..."> lädt zuverlässig eine andere Bilddatei je Breakpoint - das native, korrekte Werkzeug dafür.

Cover (Embeds vollständig zuschneiden)

Für <img>/<video> reicht .ncss-img-cover oben (natives object-fit). components/cover.css deckt den einen Fall ab, den object-fit NICHT zuverlässig löst: <iframe>-Embeds (YouTube/Vimeo/Google Maps) - object-fit wirkt in den meisten Browsern nicht auf das eingebettete Dokument.

<div class="ncss-cover-container" style="height: 20rem;">
  <iframe class="ncss-cover" src="https://www.youtube.com/embed/..." title="..." allowfullscreen></iframe>
</div>

Technik: das klassische min-width/min-height:100% + width/height:auto-Zuschnitt-Muster (kein object-fit) - braucht dafür eine EXPLIZITE aspect-ratio auf dem eingebetteten Element selbst (Default: --ncss-aspect-video, per style="aspect-ratio: ..." überschreibbar). Sich stattdessen auf die width/height-HTML-Attribute eines <iframe> zu verlassen, liefert bei einem absolut positionierten Element KEIN seitenverhältnis-treues Ergebnis (per echtem Test bestätigt). .ncss-cover-container braucht eine eigene, von außen kommende Höhe (fix, %, oder z.B. innerhalb eines .ncss-hero) - anders als .ncss-ratio-video, das die Höhe aus der Breite ableitet.

Hero-Sektion

Bild-Hintergrund mit Inhalt obenauf, components/hero.css.

<section class="ncss-hero">
  <div class="ncss-hero-media" style="background-image: url(bild.jpg)"></div>
  <div class="ncss-hero-content ncss-hero-content--filled">
    <h2>Überschrift</h2>
    <p>Text...</p>
  </div>
</section>
.ncss-heroWrapper, min-height: 22rem, overflow: clip
.ncss-hero-mediaEigene Ebene fürs Hintergrundbild (inkl. Lesbarkeits-Scrim) - background-image immer inline setzen, nie über eine Custom Property, siehe Bekannte Grenzen
.ncss-hero-content--transparentText direkt auf dem Bild (Default)
.ncss-hero-content--filledText auf blickdichter Karte obenauf
.ncss-hero--parallaxBild bewegt sich beim Scrollen langsamer als der Inhalt, via animation-timeline: view() - kein JS, kein background-attachment: fixed (auf iOS Safari absichtlich nie unterstützt)
