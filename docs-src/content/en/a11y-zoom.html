Zoom, Reflow & Text Spacing

Many people zoom pages, set a larger default font size or override line and letter spacing. A page has to cope with that without content being clipped, overlapping or only reachable by scrolling sideways.

200% zoom and text size (WCAG 1.4.4)

Text must be resizable up to 200% without assistive technology and without losing content or functionality. There are two ways to do that, and both have to work:

  • Page zoom (Ctrl/⌘ + +) scales everything - text, spacing, images. The viewport effectively gets narrower and the page switches to its narrower layout.
  • Text-only resizing (Firefox "Zoom text only", font size in browser or system settings) only changes the base font size. This only works if font sizes are relative (rem/em).

ncss sets text-size-adjust: 100% in reset.css: it stops iOS from enlarging text automatically on rotation but does not block pinch zoom. Never block zoom in the viewport meta tag - user-scalable=no or maximum-scale=1 are an accessibility failure.

<!-- Correct -->
<meta name="viewport" content="width=device-width, initial-scale=1">

<!-- Wrong: locks zoom -->
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1, user-scalable=no">

Fluid type with clamp() and rem

All font size tokens in tokens.css are fluid: clamp(min, preferred, max). The preferred value deliberately mixes a fixed rem part with a small vw part. Pure vw would ignore user zoom (the text would only depend on the window width) - the rem part makes sure a larger browser font size still takes effect.

/* from tokens.css */
--ncss-font-size-base: clamp(1rem, 0.96rem + 0.2vw, 1.13rem);
--ncss-font-size-xl:   clamp(1.8rem, 1.5rem + 1.5vw, 2.6rem);

The same applies to your own sizes: set text in rem (or via the tokens), never in px and never in vw alone. ncss sets line heights without a unit (--ncss-line-height-base: 1.6), so they scale with any font size.

One caveat with clamp(): the maximum is a fixed rem value. With page zoom rem grows, and so does the upper limit - the combination stays zoom-friendly. Still check your own clamp() values at 200%: a maximum that is too small can stop text from actually doubling in size.

Reflow at 320 CSS pixels (WCAG 1.4.10)

At a width of 320 CSS pixels (that is 400% zoom in a 1280 px wide window) content has to be readable in a single column without horizontal scrolling. Content that needs a two-dimensional layout is exempt - data tables, maps, diagrams, code.

  • .ncss-grid uses repeat(auto-fit, minmax(min(var(--ncss-grid-min), 100%), 1fr)). The min(…, 100%) stops a column from getting wider than its container - at 320 px a single column remains, without any media query.
  • reset.css sets max-width: 100% on img, video, svg and canvas, and overflow-wrap: break-word on paragraphs and headings - long words and URLs wrap instead of breaking the layout.
  • Tables sit inside .ncss-table-scroll: the table scrolls horizontally inside its own frame, the page does not. That is covered by the exception for two-dimensional content. So keyboard users can scroll the frame in older browsers too, give it tabindex="0", role="region" and a name (aria-label).
  • The header of this website is checked for wrapping between 320 and 1920 px. For your own navigation: <ncss-nav-priority> moves overflowing items into a "More" menu instead of cutting them off.
<div class="ncss-table-scroll" tabindex="0" role="region" aria-label="Pricing table">
  <table>...</table>
</div>

Container queries instead of viewport breakpoints

When you zoom, it is not just the viewport that changes but also the space each component has in its column. Container queries respond to exactly that: .ncss-container and .ncss-card-container set container-type: inline-size, and variants like .ncss-grid--cols-3 or .ncss-card--horizontal only switch via @container once their own container is wide enough. A card in a narrow sidebar therefore stays single-column at 200%, even if the window is still wide.

Give container query thresholds in rem (ncss: 24rem, 36rem, 48rem, 56rem) - then they move along with larger text.

Text spacing (WCAG 1.4.12)

Anyone who sets the following values with a browser extension or a user stylesheet must not lose any content:

PropertyMinimum (relative to font size)
Line height1.5
Spacing after paragraphs2 times
Letter spacing0.12 times
Word spacing0.16 times

ncss already meets the line height for body text out of the box (1.6). What matters is that boxes grow: buttons, badges and cards in ncss have no fixed height - their size comes from padding and content. Icon buttons (.ncss-btn--icon) calculate their size from 1lh, so they grow with the line height.

Watch out: .ncss-clamp-lines truncates text to a few lines with line-clamp. With larger spacing, more text disappears. Only use it for important content together with a way to reach the full text (a link to the detail page, <details>).

To test, paste this CSS into your developer tools (or use a "Text Spacing" bookmarklet):

* {
  line-height: 1.5 !important;
  letter-spacing: 0.12em !important;
  word-spacing: 0.16em !important;
}
p {
  margin-block-end: 2em !important;
}

No fixed heights for text

The most common cause of clipped text when zooming is a fixed height on an element that contains text - with overflow: hidden the rest disappears, without it the text overlaps whatever comes next.

  • Use min-height/min-block-size instead of height, or nothing at all - let padding and content decide the height.
  • For image areas use aspect-ratio (.ncss-ratio-video and friends) instead of fixed heights. Text does not belong in a box with a fixed aspect ratio unless that box is allowed to grow.
  • Build hero and full-screen sections with min-height instead of height: .ncss-hero uses min-height, so it grows with its content.

svh, dvh and zoom

Viewport units stay the same size when you zoom, while the text grows. A box with height: 100svh and plenty of text inside will almost certainly overflow at 200%. Use the full screen height as a minimum (min-height: 100svh), never as a fixed height for text.

Which unit ncss uses for what (svh for modal and off-canvas, lvh for scroll-linked effects, why dvh stutters there): Touch & Mobile Viewports.

/* Good: grows with its content */
.demo-intro { min-height: 100svh; }

/* Bad: text overflows when zoomed */
.demo-intro { height: 100svh; overflow: hidden; }

Target size (WCAG 2.5.8)

Click and tap targets must be at least 24 × 24 CSS pixels - or have enough spacing that a 24 px circle centred on each target does not touch another one. Links inside running text are exempt.

  • .ncss-btn gets its size from line height plus padding and is about 42 px tall at the default font size, .ncss-btn--sm about 30 px - both above 24 px.
  • Checkboxes and radios in .ncss-choice are only about 18 px themselves (--ncss-choice-size: 1.1em). That is fine as long as the <label> with its text wraps the control or is linked via for - then the whole row counts as the target.
  • Your own small icon links (social media bars, close crosses) need enough padding or spacing. 44 × 44 px is the more comfortable recommendation (WCAG 2.5.5, AAA).
