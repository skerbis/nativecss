Modal, Off-Canvas & Lightbox

Every overlay is a native <dialog>: opened via command="show-modal"/commandfor (with a small fallback script for older browsers); focus trap, Esc key and ::backdrop come from the browser. Components: components/modal.css, components/off-canvas.css, components/lightbox.css + js/lightbox.js. Class reference: Component Reference.

Dropdown / action menu (new)

Small pop-up menus outside the main navigation: the “⋯” menu on a table row, “Sort by …” or the user menu. The menu is a native popover - clicking outside and Esc close it, it sits in the top layer above everything and is placed below its trigger with CSS anchor positioning (flipped when space runs out). components/dropdown.css + js/dropdown.js, needs only colors/tokens/reset/base.

Which pattern? If an entry triggers an action on the page or picks an option (edit, delete, sort order), it is a menu following the WAI-ARIA APG “Menu Button” pattern: role="menu" with menuitem/menuitemradio/menuitemcheckbox, operated with the arrow keys - <ncss-dropdown> handles that. If the entries lead to other pages (user menu), it is a link list (disclosure) without role="menu": links stay links, Tab moves through them, screen readers list them among the page links. This variant works without JavaScript. For the main navigation use .ncss-nav-dropdown (a <details> in the nav flow).

Class / attributeEffect
<ncss-dropdown>, .ncss-dropdownWrapper around trigger and menu (inline). Only needed for role="menu" or for positioning without anchor positioning.
popovertarget + popoverConnects trigger and menu - opening, closing and light dismiss are handled by the browser.
.ncss-dropdown-toggleTrigger with an arrow that turns while open; --plain without arrow (icon button).
.ncss-dropdown-menuThe menu. --end: align with the trigger's end edge, --up: open above.
.ncss-dropdown-itemEntry (<button> or <a>); a first aria-hidden child is the icon. --danger: destructive action.
.ncss-dropdown-divider, .ncss-dropdown-heading, .ncss-dropdown-hintDivider (<hr>), group heading, end-aligned extra (e.g. a shortcut).
role="menuitemradio" / "menuitemcheckbox" + aria-checkedChoice entries with a check mark; radios are mutually exclusive per role="group".
aria-disabled="true"Entry stays focusable (APG) but cannot be chosen.
data-valueValue in ncss-dropdown-select (otherwise value or text).
Eventsncss-dropdown-select { item, value, checked }, ncss-dropdown-show, ncss-dropdown-hide; methods el.show(), el.hide().
--ncss-dropdown-min-width, --ncss-dropdown-offsetMinimum width (12rem) and gap to the trigger.

Accessibility

Keyboard (role="menu")

KeyAction
Enter / Space / ↓On the trigger: opens, focus on the first entry. ↑: on the last one.
↓ / ↑, Home / EndNext/previous entry (wrapping), first/last.
LetterJumps to the next entry starting with it (typeahead).
EnterChooses and closes, focus returns to the trigger.
SpaceOn radio/checkbox entries: toggles, the menu stays open.
Esc / TabCloses; Esc returns focus to the trigger, Tab moves on.

Screen readers

The trigger reports aria-haspopup="menu" and aria-expanded. An icon-only button (“⋯”) needs an aria-label saying what the actions are for (“More actions for invoice 2026-114”). Group headings label their role="group" via aria-labelledby and are aria-hidden themselves, so they are not read twice. The link list is a named <nav>.

Preferences

Colours from tokens (light/dark), fading only without reduced motion, borders and focus in system colours in forced colors mode. Focus inside the menu is always visible, even after a mouse click.

Without JS

Link list: fully usable (native popover). role="menu": opens and closes but is only operable with Tab - so always load js/dropdown.js.
