App building blocks

Building blocks for dashboards and admin interfaces - all native, no Web Awesome, every file usable on its own (needs only colors.css, tokens.css, reset.css, base.css). Each section shows the code and below it the result rendered from exactly that markup.

Setup

Included in ncss.css. Individually (cherry-picking), for example:

<link rel="stylesheet" href="ncss/components/avatar.css">      <!-- in the components layer -->
<script src="ncss/js/dropzone.js" defer></script>      <!-- only for <ncss-dropzone> -->
<script src="ncss/js/countdown.js" defer></script>     <!-- only for <ncss-countdown> -->
<script src="ncss/js/dismiss.js" defer></script>       <!-- only for removable tags -->

Everything else is pure CSS. Files: components/ app-shell, avatar, tag, stat, empty-state, floating-label, segmented, rating, dropzone, spinner, kbd, countdown, back-to-top; the size/density variants live in helpers/forms.css (buttons), helpers/tables.css and components/card.css.

App shell

.ncss-app-shell: sidebar, top bar, content. The sidebar is a native popover - from 48rem container width it is a fixed column, below that the very same element becomes an off-canvas panel opened by the menu button via popovertarget (ESC, light dismiss and focus return come from the browser). No JS, no duplicated navigation in the DOM. The preview below stays narrower than 48rem in narrow windows - widen the window to see the column layout.

<div class="ncss-app-shell" style="--ncss-app-shell-height: 26rem">
  <nav class="ncss-app-shell-sidebar" id="demo-appnav" popover aria-label="Main navigation">
    <button type="button" class="ncss-app-shell-close" popovertarget="demo-appnav"
            popovertargetaction="hide" aria-label="Close navigation">&times;</button>
    <a class="ncss-app-shell-brand" href="#app-shell">ImmoDesk</a>
    <h2 class="ncss-app-shell-heading" id="demo-nav-g1">Portfolio</h2>
    <ul class="ncss-app-shell-nav" role="list" aria-labelledby="demo-nav-g1">
      <li><a href="#app-shell" aria-current="page">Dashboard</a></li>

Dashboard

Page content (an actual <main> in a real app).

Customisable: --ncss-app-shell-sidebar-width (default 16rem) and --ncss-app-shell-height (height of the sticky sidebar, default 100svh - only change it for an embedded shell like this one). Without the Popover API the sidebar simply sits above the content in narrow containers. Limitation: an open off-canvas panel does not close itself when the container widens (ESC/light dismiss).

Accessibility

Keyboard

KeyAction
TabReaches the menu button (visible only in narrow containers), then top bar and content.
Enter / SpaceMenu button opens the off-canvas panel; the next Tab step moves into the navigation.
EscCloses the panel, focus returns to the menu button.

Screen reader

The sidebar is a <nav> landmark with its own aria-label. Via popovertarget the menu button reports expanded/collapsed automatically. Current page via aria-current="page".

Settings

The panel only slides in without reduced motion. The current item gets a system-colour outline in forced colours. At 400% zoom the container gets narrow - the sidebar collapses to the off-canvas panel automatically (no horizontal scrolling).

Without JS

No JS needed. Without the Popover API the navigation sits above the content in narrow containers.

Tags & chips

Difference to .ncss-badge: a badge is a status (filled, not interactive), a tag is content - a keyword, a filter chip (aria-pressed is the only state carrier) or a removable value. Removal is handled by js/dismiss.js (data-ncss-dismiss removes the closest [data-ncss-dismissible]).

Upload dropzone

<ncss-dropzone> around a real <input type="file">: drag & drop, file list with preview and remove - uploading still happens through the native field. Without JS the native field stays visible and works normally. accept also applies to dropped files, data-ncss-max-size limits the file size. Event: ncss-dropzone-change.

  <label class="ncss-dropzone-area">
    <span class="ncss-dropzone-text"><strong>Drop files here</strong> or click to choose</span>
    <span class="ncss-dropzone-hint">PDF or image, max. 10 MB</span>
    <input type="file" name="receipts" multiple accept="image/*,.pdf">
  </label>
</ncss-dropzone>

Countdown

<ncss-countdown>: digits and unit labels come from Intl.NumberFormat according to lang. Without JS the date is simply shown. The end is announced and fires ncss-countdown-end - screen reader details below.

<ncss-countdown class="ncss-countdown" datetime="2026-12-24T18:00:00+01:00">
  <time datetime="2026-12-24T18:00:00+01:00">24 December 2026, 6 pm</time>
</ncss-countdown>
<ncss-countdown class="ncss-countdown ncss-countdown--compact" datetime="2027-01-01T00:00:00+01:00"
                data-ncss-units="days hours minutes" data-ncss-done-text="Happy New Year!">
  <time datetime="2027-01-01T00:00:00+01:00">1 January 2027</time>
</ncss-countdown>

24 December 2026, 6 pm 1 January 2027

Keyboard

KeyAction
-Not interactive, no tab stop.

Instead a role="timer" line (implicitly not live) carries the state in words, updated per minute ("34 days, 5 hours and 22 minutes left"), plus the absolute date. A separate role="status" region announces the end - and every minute with data-ncss-announce="minute".

No animation, only changing numbers. Tiles wrap when zoomed.

Without JS

Back to top

A plain link to #top (per the HTML spec that is the top of the document even without a matching id). With scroll-driven animations it floats in the corner and fades in after ~40vh of scrolling - while invisible it is not reachable by Tab either. Without that capability it stays an ordinary link where it sits in the markup - so place it at the end of the page. This page's floating link is bottom right once you have scrolled a bit - lifted by --ncss-back-to-top-offset because the corner already holds the inspector button (two overlapping targets would fail WCAG 2.5.8).

<a class="ncss-back-to-top" href="#top" style="--ncss-back-to-top-offset: 3.5rem">
  <span aria-hidden="true">&uarr;</span><span class="ncss-back-to-top-label">Back to top</span>
</a>

Result (live, same classes):

↑Back to top

Limitation: reacts to scrolling of the page (scroll(root)) - if only an inner element scrolls (e.g. an app shell with its own scroll box), use a plain link there.

Accessibility

Keyboard

KeyAction
TabReachable once visible (invisible at the top of the page, hence no tab stop there).
EnterJumps to the top; with a target id="top" tabindex="-1" focus moves along.

Screen reader

A plain link with text ("Back to top", visually hidden in floating mode), arrow aria-hidden.

Settings

Reduced motion: hard switch instead of fade-in, no smooth scrolling. Forced colours: the border stays visible.

Without JS

Pure CSS; without scroll-driven animations an ordinary link where it sits in the markup.
