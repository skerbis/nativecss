WCAG 2.2 AA Checklist

A CSS framework cannot "make a site accessible". It can lay good foundations - most criteria depend on content, wording and markup, which means on you. This list shows honestly where the line runs.

How to read the tables

  • The selection covers the criteria that matter most often on typical websites - not all 55 success criteria at levels A and AA. The full list is in WCAG 2.2, a readable explanation in How to Meet WCAG.
  • "What NativeCSS provides" only applies if you use the components as described in this handbook. Your own colours, CSS and scripts need checking by you.
  • Whether your site meets a criterion can only be shown by testing the finished page - see Testing.

1 Perceivable

CriterionWhat NativeCSS providesWhat you need to do
1.1.1 Non-text Content (A).ncss-visually-hidden for text meant only for screen readers; player buttons have names; the lightbox uses alt/data-captionWrite meaningful alt text, give decorative images alt="", label icon buttons, provide chart data as text (Media)
1.2.1-1.2.5 Time-based Media (A/AA)<ncss-video-player> reads <track kind="captions|subtitles">, CC toggle, language choice; chapter tracks; playlist for a version with audio descriptionCreate captions, transcripts and, where needed, audio description - that is content no framework can supply
1.3.1 Info and Relationships (A)Native elements first (dialog, details, fieldset, tables with th); list styles rely on role="list" so the semantics surviveHeading hierarchy, landmarks, labels, th scope, marking up lists as lists. Know the exception: .ncss-table-stacked breaks table semantics (Known Limitations)
1.3.5 Identify Input Purpose (AA)-Matching autocomplete values on fields with personal data (Forms)
1.4.1 Use of Color (A)Links in running text stay underlined; the error state shows a border, toast status has text as well as colourNever convey meaning by colour alone: write error messages, explain required fields, label charts
1.4.2 Audio Control (A)Players never start by themselves; only one player plays at a timeNo autoplay with sound; videos with autoplay are always muted
1.4.3 Contrast (Minimum) (AA)Token palette with -on-soft text colours checked against their own surface, light and dark modeCheck your own colours, theme changes, text on images and videos (4.5:1, large text 3:1) - in both modes
1.4.4 Resize Text (AA)Fluid type tokens with a rem part, unitless line heights, no zoom lockYour own sizes in rem, no fixed heights for text, viewport meta tag without maximum-scale
1.4.10 Reflow (AA).ncss-grid wraps without media queries, container queries, max-width: 100% for media, word wrapping, .ncss-table-scrollCheck at 320 CSS pixels, especially your own layouts, navigation and embedded content (Zoom)
1.4.11 Non-text Contrast (AA)Focus outline (2 px, its own focus colour); native checkboxes and radiosCheck field and button borders, icons and chart lines against their background (3:1) - especially with your own theme colours
1.4.12 Text Spacing (AA)Boxes without fixed heights, icon buttons sized from 1lh, line height 1.6Test with increased spacing; only use .ncss-clamp-lines with a way to reach the full text
1.4.13 Content on Hover or Focus (AA)js/hovercard.js closes with Esc; menus and popovers close with EscYour own tooltips: dismissible with Esc, reachable with the pointer, visible as long as they are needed

2 Operable

CriterionWhat NativeCSS providesWhat you need to do
2.1.1 Keyboard (A)Native elements; the scripted components (players, menus, live search, combobox, lightbox) work with the keyboard (Keyboard)No div buttons; test your own scripts with the keyboard; check embedded third-party content
2.1.2 No Keyboard Trap (A)Native <dialog> and popover with Esc; the duplicate in the marquee is inertCheck your own overlays and embeds (maps, chat widgets)
2.2.1 Timing Adjustable (A)Toasts pause their timer while the pointer or focus is in the region and while the tab is in the background; timeout: 0 for persistent messagesDo not let important messages disappear automatically; announce session timeouts and allow extending them
2.2.2 Pause, Stop, Hide (A)Marquee: pause toggle via js/marquee.js, stops on focus; background video: pause toggle via js/video-bg.jsPut the marquee's pause button in your markup; add a pause toggle for hero videos that only use hero-video-motion.js; make your own carousels pausable
2.3.3 Animation from Interactions (AAA - not part of AA)prefers-reduced-motion: reduce reduces animations and transitions to almost zero globally; background videos do not loadNot required for AA, but important for people with vestibular disorders: let users turn off your own JS animations too
2.4.1 Bypass Blocks (A).ncss-skip-link, hidden with translate (stays out of view even with text zoom)Make the skip link the first element, <main> with the ID main as its target, use landmarks
2.4.2 Page Titled (A)-A unique <title> on every page; prefix "Error:" after form errors
2.4.3 Focus Order (A)Native dialogs move focus in and back; player menus return focus to their button when closed with EscDOM order = reading order; no positive tabindex; check layouts reordered with CSS (order, grid placement)
2.4.4 Link Purpose (In Context) (A)-Link text that names the destination - no "here" or "more" without context
2.4.6 Headings and Labels (AA)-Write descriptive headings and labels
2.4.7 Focus Visible (AA)Global :focus-visible outline in reset.css, never tied to hoverDo not remove the outline with outline: none; keep it visible with your own colours
2.4.11 Focus Not Obscured (Minimum) (AA)Focus inside the video player brings back the hidden control barSet scroll-padding-block for sticky headers and footers; cookie banners must not cover the focused element
2.5.3 Label in Name (A)-The accessible name contains the visible text (no different aria-label on buttons that have text)
2.5.7 Dragging Movements (AA)<ncss-compare> is driven by an <input type="range"> (click and keyboard work too); <ncss-dropzone> is built on a real <input type="file">Offer an alternative without dragging for your own drag-and-drop features (sorting, sliders)
2.5.8 Target Size (Minimum) (AA).ncss-btn and .ncss-btn--sm are well above 24 px; labels enlarge the click area of checkboxesGive your own small icon links enough size or spacing (Target size)

3 Understandable

CriterionWhat NativeCSS providesWhat you need to do
3.1.1 Language of Page (A)Texts in the scripted components (players, live search, lightbox) follow <html lang> (German/English)Set <html lang="en">
3.1.2 Language of Parts (AA)-Mark up passages in another language with lang
3.2.1 / 3.2.2 On Focus / On Input (A)No ncss component changes the page on focus or selection; live search only shows a result listNo automatic redirect when a <select> changes; always submit with a button
3.2.3 / 3.2.4 Consistent Navigation / Identification (AA)-Arrange and name navigation and recurring elements the same way everywhere
3.2.6 Consistent Help (A)-Contact and help links in the same place on every page
3.3.1 Error Identification (A):user-invalid border; .ncss-field-error for the error textWrite the error text and link it with aria-describedby; set aria-invalid (Forms)
3.3.2 Labels or Instructions (A).ncss-label, .ncss-label--required, .ncss-field-hintVisible labels, required, format hints before input, explain the asterisk
3.3.3 Error Suggestion (AA)-Phrase error messages with a suggested fix
3.3.4 Error Prevention (Legal, Financial, Data) (AA)-For legally or financially binding input: let people review, confirm or undo
3.3.7 Redundant Entry (A)-Pre-fill or offer information already given in the same process; keep input after errors
3.3.8 Accessible Authentication (Minimum) (AA)Native fields - password managers and pasting work as long as you do not block themNo cognitive function tests (puzzle CAPTCHAs, transcribing) without an alternative; autocomplete="current-password", one-time-code

4 Robust

CriterionWhat NativeCSS providesWhat you need to do
4.1.2 Name, Role, Value (A)Native elements; scripted components set aria-expanded, aria-pressed, aria-checked, aria-controls, aria-activedescendant; role="switch" for .ncss-switch is documentedBuild your own widgets following the ARIA Authoring Practices; set role="switch" and labels in your markup
4.1.3 Status Messages (AA)Toast region with aria-live="polite"; live search result count via role="status"; players announce state changesWrite your own status messages ("Saved", "3 results") into a live region without moving focus

4.1.1 (Parsing) has been removed in WCAG 2.2. Valid HTML without duplicate IDs is still what makes labels, aria-describedby and in-page links work.
