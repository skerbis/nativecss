Tables

helpers/tables.css - two strategies for narrow screens.

.ncss-table-scroll (default recommendation)

Horizontal scrolling, preserves full table semantics for screen readers.

<div class="ncss-table-scroll">
  <table>...</table>
</div>

.ncss-table-stacked (opt-in)

Card-stack look below 36rem (needs a data-label attribute on each <td>) - deliberately breaks programmatic table semantics in favor of readability. Only use it when the content should really read like "record cards".

<td data-label="Name">Ada Lovelace</td>

Sortable table (new)

<ncss-table-sort> around a table - or data-ncss-sort directly on the <table> - turns the column headers into buttons (WAI-ARIA APG “Sortable Table” pattern). One click sorts ascending, the next descending. Numbers (“€1,250”, “4.8”), dates (2026-11-20, also with time and time zone, 20.11.2026, <time datetime>) and text are detected per column, data-sort-value on a cell sets the value explicitly. Sorting is stable: equal values keep their previous order. components/table-sort.css + js/table-sort.js, works with .ncss-table-scroll and .ncss-table--compact. Without JavaScript it stays a normal table. The stylesheet has neutral fallbacks for every token and sits in the components layer - it works without the rest of NativeCSS and any of your own CSS overrides it.

Attribute / classEffect
<ncss-table-sort> / table[data-ncss-sort]Makes every header of the last <thead> row sortable. Newly inserted data-ncss-sort tables via ncss-content-change.
th[data-sort="false"]Column not sortable (e.g. actions).
th[data-sort-type]Force number, date or text instead of detecting it.
th[data-sort-default="descending"]First click sorts descending (e.g. “newest first”).
th[data-sort-align="end"]Button aligned to the end (number columns); also th[align="right"] and th.ncss-text-end.
th[aria-sort] in the markupThe table is already sorted that way - only the state is taken over.
td[data-sort-value]Sort value of the cell (e.g. “from €189” → 189).
data-label-sorted, -ascending, -descending, -hintTexts of the announcement (“Sorted by {column}, {direction}”) and of the hint in the <caption> (empty = no hint).
Event / methodncss-table-sort-change { column, index, direction, type }; el.sort(index, "descending").
table.is-sortableAdded by the script to every enhanced table (hook for your own CSS).
--ncss-table-sort-pad-block, --ncss-table-sort-pad-inlineCell padding the button compensates so it fills the whole cell. Default: NativeCSS padding; without tokens.css 0 (button as wide as the cell content).

Accessibility

Keyboard

Every sortable header is a real <button>: Tab reaches it, Enter/Space sorts. Focus stays on the header.

Screen readers

aria-sort="ascending"/"descending" is set only on the currently sorted <th> (the ARIA specification recommends at most one header; a missing attribute means “none”). After sorting a polite live region announces “Sorted by Price per night, ascending”. The <caption> gets a hint, read only by screen readers, that headers with buttons are sortable. The arrow in the header is aria-hidden.

Preferences

Arrow and hover from tokens (light/dark); in forced colors mode arrows in system colours, the sorted column in Highlight. The state never relies on colour alone: the arrow changes its shape.

Without JS

A normal table in markup order. With .ncss-table-stacked the header is hidden on narrow screens - there are no sort buttons there.
