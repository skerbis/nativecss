Base components

The native alternative to <wa-tab-group>, <wa-tooltip> and <wa-callout>: no ES module, no shadow DOM, the markup stays plain HTML that works without JavaScript. Each file runs on its own with colors.css, tokens.css, reset.css and base.css. Web Awesome stays optional (see Web Awesome).

Setup

Included in ncss.css. Individually (cherry-picking):

<link rel="stylesheet" href="ncss/components/tabs.css">        <!-- each in layer components -->
<link rel="stylesheet" href="ncss/components/tooltip.css">
<link rel="stylesheet" href="ncss/components/pagination.css">  <!-- pure CSS -->
<link rel="stylesheet" href="ncss/components/alert.css">       <!-- pure CSS -->
<link rel="stylesheet" href="ncss/components/preferences.css">
<script src="ncss/js/tabs.js" defer></script>      <!-- <ncss-tabs> -->
<script src="ncss/js/tooltip.js" defer></script>   <!-- fallback without interestfor -->
<script src="ncss/js/dismiss.js" defer></script>   <!-- dismiss buttons -->
<script src="ncss/js/dialog-light-dismiss.js" defer></script>  <!-- click outside closes -->
<script src="ncss/js/preferences-early.js"></script>   <!-- in <head>, before stylesheets -->
<script src="ncss/js/preferences.js" defer></script>  <!-- <ncss-preferences> -->

All scripts are standalone and also work with markup inserted later (htmx, fetch, REDAXO frontend editing): tabs as a custom element via connectedCallback, tooltip and dismiss via event delegation - see Dynamic content.

Tabs

<ncss-tabs> follows the WAI-ARIA APG "Tabs" pattern. It starts as a list of jump links above sections - without JavaScript exactly that remains (all content visible, every link jumps to its section). js/tabs.js turns it into tabs with roles, roving tabindex and arrow keys. hash mirrors the active tab in the URL (shareable, e.g. #tab-specs).

<ncss-tabs class="ncss-tabs" hash>
  <div class="ncss-tabs-list" aria-label="Product details">
    <a href="#tab-description">Description</a>
    <a href="#tab-specs">Specifications</a>
    <a href="#tab-delivery">Delivery</a>
  </div>
  <section class="ncss-tabs-panel" id="tab-description">
    <h3 class="ncss-tabs-heading">Description</h3>
    <p>Hand-made oak lamp, dimmable with a rotary knob.</p>
  </section>
  <section class="ncss-tabs-panel" id="tab-specs">
    <h3 class="ncss-tabs-heading">Specifications</h3>
    <p>LED, 2700 K, 9 W, 2 m cable, 38 cm tall.</p>
  </section>
  <section class="ncss-tabs-panel" id="tab-delivery">
    <h3 class="ncss-tabs-heading">Delivery</h3>
    <p>Ships within 3 working days, 30-day returns.</p>
  </section>
</ncss-tabs>

Accessibility

Keyboard

KeyAction
TabMoves to the active tab, the next Tab press into the panel (other tabs are not in the tab order).
← / →Previous/next tab, wrapping around (vertical: ↑ / ↓).
Home / EndFirst/last tab.
Enter / SpaceActivates the focused tab (only needed with activation="manual").

Screen reader

List role="tablist" named by aria-label, each tab role="tab" + aria-selected + aria-controls, panel role="tabpanel" with aria-labelledby. Screen readers announce e.g. "Specifications, tab, selected, 2 of 3". Vertical adds aria-orientation="vertical".

Settings

No animation when switching (nothing to turn off for reduced motion). The active tab has a 3px underline besides colour, a Highlight outline in forced colours. When zoomed, the tab bar scrolls within itself, not the page.

Without JS

Jump-link list + all sections stacked, the .ncss-tabs-heading headings structure the page. With JS they are only hidden visually.

Tooltip

Short text hint for a control (WAI-ARIA APG "Tooltip"), as native popover="hint" with interestfor: in Chromium the browser handles hover, focus, delay and Esc without any JS; js/tooltip.js provides the same behaviour elsewhere. Positioned with CSS anchor positioning, otherwise the script calculates. For links, images or profiles in an overlay use the hovercard instead - a tooltip never contains anything clickable.

<div class="ncss-cluster">
  <button type="button" class="ncss-btn ncss-btn--primary" interestfor="tip-save" aria-describedby="tip-save">Save</button>
  <span class="ncss-tooltip" id="tip-save" popover="hint" role="tooltip">Shortcut: Ctrl + S</span>

  <button type="button" class="ncss-btn ncss-btn--secondary ncss-btn--icon" aria-label="Copy" interestfor="tip-copy" aria-describedby="tip-copy">
    <span class="ncss-icon ncss-icon-copy" aria-hidden="true"></span>
  </button>
  <span class="ncss-tooltip" id="tip-copy" popover="hint" role="tooltip">Copy link to clipboard</span>
</div>

Display preferences

Not an accessibility overlay. <ncss-preferences> does not make a site accessible and fixes nothing - the site has to be accessible already. It lets visitors adapt an accessible page to their personal needs. Device settings (colour scheme, contrast, reduced motion) are the default "System" and are never silently overridden.

A "Display" button opens a popover with native controls: colour scheme, contrast and motion (each System/…), text size 100/115/130 %, font, text spacing per WCAG 1.4.12, always underline links, stronger focus. Every change applies to the whole page at once and is saved (localStorage). It works through attributes on <html> - colors.css and reset.css react to them, no component needs its own rules. js/preferences-early.js in the <head> sets the attributes before first paint (no flash) and replaces theme-toggle-early.js (same storage key, one mechanism).

<ncss-preferences></ncss-preferences>

Font: with components/preferences-fonts.css (opt-in, not part of ncss.css) the panel offers three reading fonts - each name shown in its own typeface as a preview. Only body text and headings change (--ncss-font-family-base/-heading), code stays monospace. All fonts live in dist/fonts/ (SIL Open Font License, license texts and notes in dist/fonts/README.md), no Google Fonts request. The browser downloads a file only when it is needed: the selected font - and the preview fonts when the panel is opened.

Motion "Full" is only possible as an explicit choice: it lifts the global damping NativeCSS applies for system "reduced motion", and the panel points this out. Effects a component explicitly offers only under prefers-reduced-motion: no-preference stay off - CSS cannot reinterpret a system setting. "Reduced" works everywhere: transitions, animations, scroll-driven effects and all scripts (they check data-motion too). Increased contrast uses the same values as prefers-contrast: more.

Dialogs: clicking outside closes

Modal, off-canvas, command palette and lightbox close when the dimmed area is clicked - natively via <dialog closedby="any">. js/dialog-light-dismiss.js makes this the default (sets closedby="any" on every ncss dialog without its own attribute, including ones inserted later and opened via JS) and emulates it in browsers without closedby. Opt out per dialog with the native attribute: closedby="closerequest" (Esc + buttons only) or closedby="none" (buttons only, e.g. long forms).

<div class="ncss-cluster">
  <button type="button" class="ncss-btn ncss-btn--primary" command="show-modal" commandfor="ld-demo">Open modal</button>
  <button type="button" class="ncss-btn ncss-btn--secondary" command="show-modal" commandfor="ld-form">Form (closedby="none")</button>
</div>
<dialog id="ld-demo" class="ncss-modal" aria-labelledby="ld-demo-title">
  <button type="button" class="ncss-dialog-close" command="close" commandfor="ld-demo" aria-label="Close">&times;</button>
  <div class="ncss-modal-header"><h3 id="ld-demo-title">Clicking outside closes</h3></div>
  <div class="ncss-modal-body"><p>Click the dimmed area, press Esc or use the button. Text inside can be selected without the dialog closing.</p></div>
</dialog>
<dialog id="ld-form" class="ncss-modal" closedby="none" aria-labelledby="ld-form-title">
  <div class="ncss-modal-header"><h3 id="ld-form-title">Long form</h3></div>
  <div class="ncss-modal-body"><p>Only the button closes this one - neither clicking outside nor Esc discard input by accident.</p></div>
  <div class="ncss-modal-footer"><button type="button" class="ncss-btn ncss-btn--primary" command="close" commandfor="ld-form">Done</button></div>
</dialog>

Closing goes through requestClose(): the cancel event fires first, event.preventDefault() keeps the dialog open (e.g. "Discard unsaved changes?"). A text selection that starts in the panel and ends outside does not close it. Setup: <script src="ncss/js/dialog-light-dismiss.js" defer></script>.

KeyAction
EscCloses (except with closedby="none").

Screen reader

Without JS
