Forms

Native elements are fully styled (helpers/forms.css), no JS reimplementations. Live example: demo/forms.html.

Base Fields

ClassPurpose
.ncss-fieldLabel+input+hint as a vertical group
.ncss-label / --requiredField label, --required adds a red *
.ncss-input / .ncss-select / .ncss-textareaConsistent look, including :user-invalid error state
.ncss-field-hint / -errorHelp text / error text below a field

Other Field Types (styled cross-browser)

TypeNotes
type="file"The biggest cross-browser difference of any field type - ::file-selector-button (+ ::-webkit-file-upload-button for older Safari) brings the browser button up to .ncss-btn--secondary looks
type="color"Swatch surface via ::-webkit-color-swatch(-wrapper)/::-moz-color-swatch matched to ncss radius, fixed height matching the other fields
type="date/time/datetime-local/month/week"Calendar/clock icon follows the theme automatically (color-scheme), no custom adjustment needed
type="search"appearance: none needed, otherwise Safari rounds the field fully off on its own
type="number"Native spinner arrows deliberately NOT removed - real functionality, no reason to cut it

Checkbox, Radio & Switch

.ncss-choiceCheckbox/radio row - native elements, only accent-color + alignment
.ncss-switchToggle switch built from <input type="checkbox">, redrawn via appearance:none, no JS. Add role="switch" in markup
.ncss-rangeUnified <input type="range">, track/thumb matched

Grouping & Feedback

fieldset / legendFully styled with no dedicated class (like <blockquote>) - replaces the native 3D border
progress / meteraccent-color for the base color. meter deliberately keeps its own green/yellow/red rating logic instead of the brand color
outputHighlighted presentation for a computed result

Buttons

.ncss-btn + --primary/--secondary/--danger. Every variant has REAL :active feedback (not just :hover) - see Touch & Mobile Viewports for the reasoning.
