Styled Dropdowns (opt-in)

The native suggestion list of a <datalist> AND the options popup of a <select> are not stylable via CSS in any browser (checked as of 2026) - for <select> there's now a CSS path via appearance: base-select, which ncss currently only enables in Chrome/Edge 135+ (see Component Reference for why Safari is deliberately excluded), and none at all for <datalist>.

components/combobox.js (opt-in) replaces the native popup look with a real, styled dropdown list in both cases - the original markup stays unchanged (<input list>/<datalist> or <select>/<option>), full native functionality remains without JS (progressive enhancement, no functional loss). For <select> it kicks in exactly where ncss does NOT enable appearance: base-select (Firefox and currently also Safari) - where the native technique already delivers a styled popup (Chrome/Edge), the script does nothing.

<script src="components/combobox.js" defer></script>

Always include <button><selectedcontent> as the first child, even for a plain text select - optional per spec (the browser generates a matching default button otherwise), but it keeps the behavior consistent and predictable across browsers.

<select class="ncss-select">
  <button type="button">
    <selectedcontent></selectedcontent>
  </button>
  <option>Option A</option>
  <option>Option B</option>
</select>

Rich <option> content (natively only with appearance: base-select, replicated by components/combobox.js elsewhere): since the "Customizable Select" extension, <option> may contain arbitrary child elements (icon+label instead of just text), and the same <button><selectedcontent> then also controls how the current selection is shown in its closed state. "The Golden Rule of Customizable Select": text stays mandatory (visible or via .ncss-visually-hidden), icons are an addition, never a replacement.

<select class="ncss-select">
  <button type="button">
    <selectedcontent></selectedcontent>
  </button>
  <option value="apple">
    <span aria-hidden="true">🍎</span>
    <span>Apple</span>
  </option>
</select>

components/combobox.js replicates the same rich content for the JS fallback path (Firefox and currently also Safari) - <option> child elements are cloned 1:1 into the custom dropdown list instead of just the squashed-together text. Visually identical result, confirmed with real tests in Chromium (native) as well as WebKit and Firefox (both JS fallback).

Input Group

components/input-group.css - multiple form controls visually fused into ONE unit (shared border line instead of a gap, only the outer corners rounded). Covers two cases: field + button (search bar) and multiple fields side by side (e.g. first name/last name). Deliberately NOT called "form group" - too easy to confuse with the already-existing <fieldset>/<legend> grouping (semantics rather than pure styling).

<label class="ncss-visually-hidden" for="search">Search term</label>
<div class="ncss-input-group">
  <input class="ncss-input" type="search" id="search" placeholder="Search…">
  <button type="submit" class="ncss-btn ncss-btn--primary">Search</button>
</div>

Accessibility: a placeholder is NOT a substitute for a label - it disappears once text is entered, and isn't reliably announced as the field's name by every screen reader. Every field needs a real <label>, visually hidden via .ncss-visually-hidden if needed - as a sibling BEFORE the .ncss-input-group, not nested inside it (otherwise it would incorrectly count as :first-child and the corner rounding would land on the invisible label instead of the first real field). For multiple tightly-fused fields with no room for a per-field sibling label (e.g. first/last name), aria-label directly on the <input> is the right technique, without changing the group's child structure:

<div class="ncss-input-group">
  <input class="ncss-input" aria-label="First name" placeholder="First name">
  <input class="ncss-input" aria-label="Last name" placeholder="Last name">
</div>

Currently covers .ncss-input/-textarea/.ncss-btn as direct children - not (yet) .ncss-select-wrapper (its visible border sits on the inner <select>, not the wrapper itself).
