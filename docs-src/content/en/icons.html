Icons

Three ways, one model: icons are 1em tall and take the text colour (currentColor). Size via font-size or --ncss-icon-size, colour via color.

Core icons

Custom SVGs as CSS mask-image: no markup content, no request, no JavaScript. 24-unit grid with round caps - line glyphs (arrows, chevrons, plus/minus) slightly bolder than pictograms. Click a tile to copy its markup.

<ncss-icon>: every Phosphor icon

Loads an icon from vendor/phosphor/ (Phosphor Icons, MIT) and inserts it sanitised as inline SVG with fill="currentColor". Each file is fetched only once per page. helpers/icons.css reserves the space beforehand - nothing jumps.

<link rel="stylesheet" href="dist/ncss.css">   <!-- or just dist/helpers/icons.css -->
<script src="dist/js/icon.js" defer></script>

<ncss-icon name="house"></ncss-icon>
<ncss-icon name="heart" weight="fill" label="Favourite"></ncss-icon>

Attributes

AttributeEffect
namePhosphor name, e.g. house, arrow-right, gear-six (search in the builder)
weightregular (default), thin, light, bold, fill, duotone
labelmakes the icon meaningful: role="img" + aria-label. Without label it is decorative (aria-hidden="true").
srcload any SVG file of your own instead of name (sanitised as well)
data-ncss-icon-pathicon folder, on the element or an ancestor (e.g. <html>), relative to the page. Default: vendor/phosphor/ relative to dist/js/icon.js.

Events: ncss-icon-load and ncss-icon-error (bubbling, detail.url).

Without JavaScript <ncss-icon> stays empty

Before the script loads (or without JS) the element is invisible, but its space is reserved. Put an icon that carries meaning (e.g. a button without text) in as a core icon or via a sprite - or keep visible text next to it.

Custom icon path

<html lang="en" data-ncss-icon-path="/assets/phosphor/">
<!-- expects /assets/phosphor/regular/house.svg, /assets/phosphor/bold/house-bold.svg … -->
<ncss-icon src="/assets/logo-mark.svg" label="Logo"></ncss-icon>

SVG sprite: Phosphor without JavaScript

A sprite is one SVG file with a <symbol> per icon. Referenced via <use> it needs no script, inherits currentColor and is loaded and cached once. .ncss-icon-sprite (in helpers/icons.css) sets size and fill.

From the command line

Plain Node script, no npm. Symbol IDs are the Phosphor file names (house, heart-fill, star-duotone) - weight for all via --weight, per icon via name:weight. An unknown name prints suggestions (home → house).

node tools/icons/sprite.mjs house bell heart:fill star:duotone arrow-right gear-six --out=icons.svg

<use href="file.svg#id"> with an external file only works from the same origin - ship the sprite with the site, not from a foreign CDN.

      Font Awesome as an alternative

      Font Awesome Free is self-hosted under vendor/fontawesome/ (web font + SVGs, also the basis of <wa-icon> in the Web Awesome bridge). Not part of ncss.css - only include it when the project uses FA anyway. Components like .ncss-dialog-close only style the surface, so every icon is swappable:

      <link rel="stylesheet" href="vendor/fontawesome/css/fontawesome.min.css">
<link rel="stylesheet" href="vendor/fontawesome/css/solid.min.css">
<link rel="stylesheet" href="dist/integrations/fontawesome-font-display-fix.css">

<button class="ncss-dialog-close" aria-label="Close">
  <span class="ncss-icon ncss-icon-close" aria-hidden="true"></span>   <!-- core icon -->
  <i class="fa-solid fa-xmark" aria-hidden="true"></i>              <!-- or Font Awesome -->
  <ncss-icon name="x"></ncss-icon>                               <!-- or Phosphor -->
</button>

      integrations/fontawesome-font-display-fix.css sets font-display: swap for the FA fonts (otherwise icons stay invisible until loaded).

      Using icons accessibly

      • Decorative or meaningful? If text is next to it, the icon is decoration: aria-hidden="true" (automatic for <ncss-icon>). If it carries meaning on its own (status icon without text), it needs a name: label="…" or role="img" aria-label="…".
      • Icon-only buttons need aria-label on the button (not the icon) - and an icon that is visible without JS (core icon or sprite). A tooltip does not replace the name.
      • Never convey status by colour or icon alone: say warning/error in words too.
      • High contrast mode (Windows forced-colors): core icons switch to the system colour CanvasText, <ncss-icon> and sprites follow the forced text colour via currentColor - all stay visible.
      • Size: icons scale with the font, so with browser zoom and text size too. Keep hit areas at least 24×24 px (better 44×44) - the button defines the area, not the icon.
      <!-- decoration: the text carries the meaning -->
<a href="/"><span class="ncss-icon ncss-icon-home" aria-hidden="true"></span> Home</a>

<!-- icon only: name on the button -->
<button class="ncss-btn ncss-btn--icon" aria-label="Delete">
  <span class="ncss-icon ncss-icon-trash" aria-hidden="true"></span>
</button>

<!-- icon carries meaning on its own -->
<span class="ncss-icon ncss-icon-success" role="img" aria-label="Done"></span>
