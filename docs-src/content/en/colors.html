Colors & Surfaces

light-dark() is the sole dark mode mechanism - no second dark stylesheet, no .dark class. ONE value per token covers both light and dark.

Semantic Tokens

Graded Scales

Each of the six color families (brand, brand-2, neutral, success, warning, danger) has derived steps, computed via color-mix() from EXACTLY ONE base value:

SuffixMeaning
-100 / -300Lighter/subtler (badge/chip background)
-500The base color itself (alias)
-700 / -900Darker/bolder, stays dark in BOTH modes
-on-softMatching text color for a -100/-300 surface

Change a brand color in theme.css, the whole scale follows automatically - see Theming.

Colored Surfaces

helpers/surfaces.css: .ncss-surface--brand / --brand-2 / --neutral - background + guaranteed matching text color (900 step + #fff) in a single class, instead of an inline style with hand-maintained contrast.

<div class="ncss-surface--brand">Always readable contrast</div>

Web Awesome on colored surfaces: a <wa-input> or similar renders its label/value in its own shadow DOM - color alone doesn't reach it. webawesome-bridge.css bridges --wa-form-control-label-color and others automatically as soon as .ncss-surface--* or .ncss-text-light/-dark are in play.

Forced Light/Dark Text

.ncss-text-light/-dark (+ -100/-300/-700/-900 as opacity steps) - fixed to white/black, INDEPENDENT of the theme. For surfaces whose color doesn't run through ncss tokens (photo, video poster). UIkit's uk-light counterpart.

Manual Theme Override

[data-theme="light"]/[data-theme="dark"] on <html> forces a color scheme independent of the system setting (e.g. for a UI toggle). Locally on a single element: .ncss-scheme-dark/-light (helpers/surfaces.css).
