Framework integration

NativeCSS needs no bundler - if you already use one, you can import it via npm. The web components (<ncss-…>) are light-DOM elements without dependencies and work like plain HTML in any framework.

Two ways

Without a bundler

Copy dist/ into the public folder and include it via <link> - works with any server framework.

With a bundler (Vite, Astro …)

// npm i @skerbis/nativecss
import "@skerbis/nativecss";            // = dist/ncss.css
import "@skerbis/nativecss/theme.css";
import "@skerbis/nativecss/dist/js/tabs.js"; // only the scripts you need

Laravel (Blade)

<!-- resources/views/layouts/app.blade.php, files in public/ncss/ -->
<link rel="stylesheet" href="{{ asset('ncss/ncss.css') }}">
<link rel="stylesheet" href="{{ asset('ncss/theme.css') }}">

Wrap recurring markup in a Blade component - the classes stay NativeCSS:

<!-- resources/views/components/card.blade.php -->
<article {{ $attributes->merge(['class' => 'ncss-card ncss-border ncss-radius-lg']) }}>
  <div class="ncss-card-body ncss-stack">
    <h3>{{ $title }}</h3>
    {{ $slot }}
  </div>
</article>

<!-- usage -->
<x-card title="Hello">Content</x-card>

With Vite: npm i @skerbis/nativecss and import "@skerbis/nativecss" in resources/js/app.js.

Symfony (Twig)

{# templates/base.html.twig, files e.g. in assets/ncss/ (AssetMapper) #}
<link rel="stylesheet" href="{{ asset('ncss/ncss.css') }}">
<link rel="stylesheet" href="{{ asset('ncss/theme.css') }}">

Recurring building blocks as Twig macros or Twig components (Symfony UX) - they output NativeCSS markup.

Astro, Eleventy, Hugo

  • Astro: import "@skerbis/nativecss"; in the layout frontmatter (or files in public/ + <link>); component scripts via <script src="…/dist/js/tabs.js"> only in the components that need them.
  • Eleventy / Hugo: serve dist/ via passthrough copy (11ty) or from static/ (Hugo), two <link> lines in the base layout, shortcodes/partials output NativeCSS markup.

React, Vue, Svelte

The web components are ordinary custom elements without shadow DOM - classes, tokens and theme.css apply as everywhere. Two things to note:

  • Events are named ncss-<component>-<action> (e.g. ncss-compare-change). Subscribe via a ref with addEventListener - it works the same in every framework.
  • Vue must know that ncss-* are not Vue components:
// vite.config.js
vue({ template: { compilerOptions: {
  isCustomElement: (tag) => tag.startsWith("ncss-")
} } })
// React: subscribe to an event via a ref
const ref = useRef(null);
useEffect(() => {
  const el = ref.current;
  const onChange = (e) => console.log(e.detail);
  el.addEventListener("ncss-compare-change", onChange);
  return () => el.removeEventListener("ncss-compare-change", onChange);
}, []);
return <ncss-compare ref={ref}>…</ncss-compare>;

Class-based effects with a script (count-up, marquee …) need the ncss-content-change event after rendering new content - see Dynamic content. Custom elements initialise themselves.

htmx and Alpine.js

Server-rendered HTML is NativeCSS's natural partner. For htmx a tiny file is enough:

// assets/js/htmx-ncss.js
document.addEventListener("htmx:load", function (event) {
  document.dispatchEvent(new CustomEvent("ncss-content-change", {
    detail: { root: event.detail.elt }
  }));
});

Alpine.js manages state (e.g. x-show) - but for dialogs, accordions and tabs prefer the native NativeCSS variants (<dialog> + command, <details>, <ncss-tabs>); they already bring keyboard support and ARIA.
