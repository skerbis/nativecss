User Preferences

Operating systems and browsers offer settings for less motion, more contrast, less transparency, custom system colors and light/dark mode. CSS can query them with media queries - ncss does so centrally and inside the components where it's needed.

Try the Settings

The checkboxes simulate each setting on the sample area only. The real settings live, for example, under "Accessibility > Display" on macOS and under "Accessibility" or "Contrast themes" on Windows; Chrome/Edge DevTools can emulate them in the "Rendering" panel.

Reduced Motion: prefers-reduced-motion

Large movements, parallax and zoom can cause dizziness and nausea (WCAG 2.3.3). So reset.css globally caps all animations and transitions to practically zero and turns off smooth scrolling - no component has to check this on its own. ::details-content is listed explicitly because the universal selector doesn't reach that pseudo-element.

/* reset.css */
@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after, *::details-content {
    animation-duration: 0.01ms !important;
    animation-iteration-count: 1 !important;
    transition-duration: 0.01ms !important;
    scroll-behavior: auto !important;
  }
}

Where the global rule isn't enough, components take care of the rest:

  • Marquee .ncss-marquee - the animation only starts under no-preference; with reduced motion the row becomes a regular horizontally scrollable area and the copy disappears.
  • Scripts check matchMedia("(prefers-reduced-motion: reduce)"): js/backdrop.js doesn't cycle images automatically, js/count-up.js shows the final number straight away, js/view-transitions.js skips transitions, js/video-card.js doesn't play previews.
  • Background video - CSS can't stop <video autoplay>. That's why js/hero-video-motion.js removes autoplay and pauses the video under reduced motion; the poster stays visible.
  • Light/dark switch - the soft cross-fade while switching only runs under no-preference.

For your own effects: write motion as an addition, not as the starting state. Then "no motion" is automatically the stable case.

.my-teaser {
  opacity: 1;
}
@media (prefers-reduced-motion: no-preference) {
  .my-teaser {
    animation: fade-in 600ms ease-out both;
  }
}
<!-- Only on pages with a background video in the hero -->
<script src="dist/js/hero-video-motion.js" defer></script>

Regardless of the setting: anything that moves automatically for more than 5 seconds needs a way to pause it (WCAG 2.2.2) - for the marquee that's [data-ncss-marquee-toggle], see Media.

More Contrast: prefers-contrast

The ncss color tokens are already calibrated for AA contrast (see Colors & Surfaces), so there's no global override. The video player uses prefers-contrast: more: a darker gradient behind the control bar and a more distinct timeline over moving footage.

In your own design, the query pays off wherever you deliberately went subtle - muted helper text, hairline borders, text on images:

@media (prefers-contrast: more) {
  .my-area {
    --ncss-color-text-muted: var(--ncss-color-text);
    --ncss-color-border: currentColor;
  }
}

Reduced Transparency: prefers-reduced-transparency

Frosted-glass surfaces (backdrop-filter) and semi-transparent backgrounds make reading harder because whatever is underneath shows through. Under prefers-reduced-transparency: reduce, ncss gives the video player's on-screen flash and the caption of <ncss-scroll-video> a solid surface.

.my-glass-bar {
  background-color: color-mix(in oklch, var(--ncss-color-surface) 60%, transparent);
  backdrop-filter: blur(8px);
}
@media (prefers-reduced-transparency: reduce) {
  .my-glass-bar {
    background-color: var(--ncss-color-surface);
    backdrop-filter: none;
  }
}

Forced Colors: forced-colors

In Windows contrast themes (and similar modes), the browser replaces every color with a small palette of system colors, and background images and shadows disappear. Anything that was only visible through color, a shadow or background-color is gone. ncss handles this with @media (forced-colors: active) in many components, including icons, badges, tags, toasts, the command palette, section navigation, spinner, before/after, segmented control and the media players.

Take icons: .ncss-icon is a shape cut out with mask-image and filled with background-color: currentColor - in forced colors mode it came out empty. The fix:

@media (forced-colors: active) {
  .ncss-icon {
    forced-color-adjust: none;
    background-color: CanvasText;
  }
}

Rules of thumb for your own components:

  • Never show state through background color alone - a border (even a transparent one) becomes visible in forced colors mode.
  • Use the system color keywords: Canvas, CanvasText, LinkText, ButtonText, Highlight, GrayText.
  • Use forced-color-adjust: none sparingly and set system colors yourself when you do - never to override the user's choice.
  • The :focus-visible ring uses outline, so it stays visible in forced colors mode too.

Light and Dark: prefers-color-scheme and light-dark()

Every color token in colors.css is defined with light-dark() and follows the system setting automatically through color-scheme: light dark. data-theme="light" or "dark" on <html> overrides it; .ncss-scheme-dark/-light switch individual areas. Both palettes are contrast-checked - your own colors have to pass in both modes.

:root {
  color-scheme: light dark;
  --ncss-color-text: light-dark(#1a1a1a, #f0f0f0);
  --ncss-color-focus-ring: light-dark(#0057d8, #6ea8ff);
}
:root[data-theme="dark"] {
  color-scheme: dark;
}

A toggle is optional: js/theme-toggle.js stores the choice, follows the system live when nothing is stored, and sets aria-pressed plus a changing aria-label that says what the click will do ("Switch to dark theme"). js/theme-toggle-early.js in the <head> prevents a flash of the wrong mode.

<head>
  <script src="dist/js/theme-toggle-early.js"></script>
  <link rel="stylesheet" href="dist/ncss.css">
  <script src="dist/js/theme-toggle.js" defer></script>
</head>
...
<button type="button" class="ncss-theme-toggle" data-ncss-theme-toggle>
  <span class="ncss-icon ncss-icon-moon ncss-theme-icon-dark" aria-hidden="true"></span>
  <span class="ncss-icon ncss-icon-sun ncss-theme-icon-light" aria-hidden="true"></span>
</button>

The data-ncss-theme-toggle="cycle" variant steps through System, Light and Dark and shows the current name in a child element [data-ncss-theme-label].
