Screen Readers & ARIA

A screen reader doesn't read what you see - it reads the accessibility tree: the role, name and state of every element. Clean HTML provides most of that; ARIA only fills the gaps HTML can't.

Accessible Names

Every control needs a name that says what it does (WCAG 4.1.2). In order of preference:

  1. Visible text - button labels, link text, <label for>. Best for everyone, including voice control users ("click Save"). If there's visible text, the accessible name must contain it (WCAG 2.5.3).
  2. .ncss-visually-hidden - extra text for screen readers only, e.g. inside icon buttons, or to turn "Read more" into "Read more about pricing". Translation tools pick it up too.
  3. aria-label - when no text fits in the markup, e.g. on the .ncss-dialog-close button showing &times;.
  4. aria-labelledby - points at existing text, e.g. from a dialog to its heading.

The icon itself (.ncss-icon, <svg>) gets aria-hidden="true" - otherwise a screen reader may read out a file name, or nothing useful at all. .ncss-btn--icon always needs a name.

A screen reader announces: "Open search, button" · "Copy link, button" · "Menu, button".

<!-- 1. Hidden text -->
<button type="button" class="ncss-btn ncss-btn--secondary ncss-btn--icon">
  <span class="ncss-icon ncss-icon-search" aria-hidden="true"></span>
  <span class="ncss-visually-hidden">Open search</span>
</button>

<!-- 2. aria-label -->
<button type="button" class="ncss-btn ncss-btn--secondary ncss-btn--icon" aria-label="Copy link">
  <span class="ncss-icon ncss-icon-copy" aria-hidden="true"></span>
</button>

<!-- 3. Best: visible text -->
<button type="button" class="ncss-btn ncss-btn--secondary">
  <span class="ncss-icon ncss-icon-menu" aria-hidden="true"></span>
  Menu
</button>

Spell out symbol keys like ⌘ in .ncss-kbd with <abbr title="Command"> or aria-label - the glyph alone is often skipped or misread.

Landmarks

Landmarks are a screen reader's jump points: <header> (banner), <nav> (navigation), <main> (main), <aside> (complementary), <footer> (contentinfo). The HTML elements carry the role already - no extra role="navigation" needed.

  • Exactly one <main> per page - which is also the skip link's target.
  • Multiple <nav> elements each need an aria-label, otherwise users just hear "navigation" three times. Don't put the word "navigation" in the label - the screen reader announces the role itself.
  • <header>/<footer> only count as landmarks directly under <body>, not inside <article> or <section>.
  • A <section> only becomes a region once it has an accessible name (aria-labelledby pointing at its heading) - for ordinary sections, a heading is enough.
<body>
  <a href="#main" class="ncss-skip-link">Skip to content</a>
  <header class="ncss-topbar">
    <nav class="ncss-nav" aria-label="Main">...</nav>
  </header>
  <nav class="ncss-breadcrumb" aria-label="Breadcrumb">...</nav>
  <main id="main">
    <h1>Page title</h1>
    ...
  </main>
  <footer>
    <nav aria-label="Legal">...</nav>
  </footer>
</body>

Headings

Many screen reader users navigate by the list of headings first. So:

  • One <h1> per page, then <h2>, <h3> without skipping levels.
  • Pick the level by structure, not by the size you want - the typography classes handle the look (see Typography).
  • Bold text isn't a heading, and headings aren't for decorative lines. A kicker like .ncss-eyebrow stays a <p> next to the actual heading.

Live Regions in the Components

When content changes without a page load, a screen reader only finds out through a live region (WCAG 4.1.3). The catch: the region has to exist in the DOM before text is written into it - which is why the ncss scripts create theirs right at startup.

A screen reader reads the highlighted link as "Screen Readers & ARIA, current page, link". In ncss the highlight hangs directly off the attribute - no extra .active class, so appearance and semantics can't drift apart.

No ARIA Is Better Than Bad ARIA

ARIA only changes what a screen reader announces - never how something behaves. A <div role="button"> doesn't become focusable or respond to Enter. Wrong ARIA is worse than none, because it promises things that don't work.

  • Native element over role: <button> instead of role="button", <dialog> instead of role="dialog", <details> instead of a homemade accordion with aria-expanded.
  • No redundant roles (<nav role="navigation">, <button role="button">).
  • Never put aria-hidden="true" on focusable elements - use inert for whole inactive areas (as the marquee does for its copy and the drilldown for its root list).
  • An ARIA state must always match the visible state - if you set aria-expanded, reset it on close too.
  • A list with list-style: none loses its list semantics in VoiceOver/Safari - so ncss only uses custom markers together with role="list" in the markup.
  • Pure graphics like .ncss-sparkline stay aria-hidden; the real values sit next to them in a .ncss-visually-hidden table.
