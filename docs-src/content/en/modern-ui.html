Modern UI

Eight modern building blocks - each one its own CSS file (plus at most one script), working on their own with just colors.css/tokens.css/reset.css/base.css. Interactive parts are light-DOM custom elements around native markup: without JavaScript there is always a sensible baseline.

Bento grid

.ncss-bento is its own container: when the grid gets too narrow for a span (.ncss-col-span-2/-3), the span is dropped instead of overflowing sideways. Every tile is a container too - in very narrow tiles headings get smaller and hyphenate by language rules (set lang). Rows grow with their content (minmax(--ncss-bento-row-height, auto)). Presets without classes on the tiles: .ncss-bento--hero (1st tile 2×2, 4th tall, every 6th from the 5th wide) and .ncss-bento--mosaic.

<div class="ncss-bento ncss-bento--hero">
  <article class="ncss-card ncss-border ncss-radius-lg">...</article>
  <article class="ncss-card ncss-border ncss-radius-lg">...</article>
</div>

Thresholds: 1 column below 26rem, a span of 3 becomes a full row below 40rem - matching the default --ncss-bento-min: 12rem. grid-auto-flow: dense changes only the visual order, not the tab order.

Spotlight

A light follows the mouse pointer, and the border segment closest to the pointer lights up (same mask-ring technique as .ncss-glow-border). data-ncss-spotlight on a group: one listener for all surfaces, neighbours catch the edge of the light. Touch is ignored.

<div class="ncss-grid" data-ncss-spotlight>
  <article class="ncss-card ncss-spotlight">...</article>
  <article class="ncss-card ncss-spotlight ncss-spotlight--strong">...</article>
</div>
<script src="ncss/js/spotlight.js" defer></script>

Tokens: --ncss-spotlight-color, --ncss-spotlight-border, --ncss-spotlight-size (24rem). Attribute data-reach (px, default 160) for the neighbour reach.

Before/after compare

<ncss-compare> lays a real <input type="range"> over two images: mouse, touch (drag horizontally, vertical still scrolls), keyboard and screen readers all come from the browser. The script only sets --ncss-compare-position and aria-valuetext.

<ncss-compare style="--ncss-compare-ratio: 4 / 3">
  <img class="ncss-compare-before" src="before.jpg" alt="Kitchen before the renovation">
  <img class="ncss-compare-after" src="after.jpg" alt="Kitchen after the renovation">
  <span class="ncss-compare-label" aria-hidden="true">Before</span>
  <span class="ncss-compare-label ncss-compare-label--end" aria-hidden="true">After</span>
  <input class="ncss-compare-range" type="range" min="0" max="100" value="50"
         aria-label="Move divider: before on the left, after on the right">
</ncss-compare>
<script src="ncss/js/compare.js" defer></script>

Attribute data-label-value (spoken value, e.g. "{n}% old"; default German/English by the nearest lang), event ncss-compare-change (detail.value), property el.value. Without JS the slider is hidden (a slider that does not move the images would be misleading).

Expanding panels

Pure CSS: the hovered or focused panel grows (flex-grow), otherwise the active one (.ncss-expand-panel--active or aria-current). Below a 36rem container width the panels stack and grow in height instead. Panels are links or buttons - reachable with Tab.

<div class="ncss-expand-panels">
  <a class="ncss-expand-panel ncss-expand-panel--active" href="/alps">
    <span class="ncss-expand-panel-media"><img src="alps.jpg" alt=""></span>
    <span class="ncss-expand-panel-title">Alps</span>
    <span class="ncss-expand-panel-body">Six routes above 3000 m.</span>
  </a>
</div>

Tokens: --ncss-expand-height (24rem), --ncss-expand-grow (4), --ncss-expand-collapsed/-expanded (stacked heights).

Command palette

<ncss-command-palette> around a <dialog class="ncss-command">. WAI-ARIA combobox + listbox like the live search: focus stays in the input, ↑/↓ choose, Enter runs the item (a link follows its href, a button is clicked), Esc closes. The ⌘K / Ctrl+K shortcut is opt-in via shortcut="k".

<button type="button" command="show-modal" commandfor="cmd">Commands</button>
<ncss-command-palette shortcut="k">
  <dialog id="cmd" class="ncss-command" aria-label="Command palette" closedby="any">
    <div class="ncss-command-search">
      <input class="ncss-command-input" type="text" aria-label="Search commands">
    </div>
    <div class="ncss-command-list" aria-label="Commands">
      <div class="ncss-command-group">
        <p class="ncss-command-group-label">Pages</p>
        <a class="ncss-command-item" href="/" data-keywords="start home">Home</a>
        <button class="ncss-command-item" type="button">Dark theme</button>
      </div>
    </div>
    <p class="ncss-command-empty" hidden>No results</p>
  </dialog>
</ncss-command-palette>
<script src="ncss/js/command-palette.js" defer></script>

Events: ncss-command-select (cancelable, detail.item), ncss-command-show/-hide. Methods: show(), hide(), toggle(), filter(text). Without native command/commandfor the script opens the dialog itself - js/command-fallback.js is not required.

Hover cards

<ncss-hovercard>: the first child is the link, .ncss-hovercard the card (popover="hint", top layer, anchor positioning with automatic flipping). With interestfor (Chromium) the browser handles hover, focus, delays, Esc and long-press with no JS at all. Elsewhere the script opens after 400 ms on hover or keyboard focus, keeps the card open while the pointer or focus is inside it (WCAG 1.4.13) and closes on Esc. Without anchor positioning it computes the position itself.

<ncss-hovercard>
  <a href="/team/ada" interestfor="hc-ada">Ada Lovelace</a><span id="hc-ada" class="ncss-hovercard" popover="hint">
    <span class="ncss-hovercard-header">
      <span class="ncss-hovercard-avatar" aria-hidden="true">AL</span>
      <span><strong class="ncss-hovercard-title">Ada Lovelace</strong>
            <span class="ncss-hovercard-meta">Mathematician</span></span>
    </span>
    <span class="ncss-hovercard-text">...</span>
  </span></ncss-hovercard>
<script src="ncss/js/hovercard.js" defer></script>

In running text use a <span> as the card and leave no line break between </a>, the card and </ncss-hovercard> - otherwise a space remains before the following punctuation. Attributes delay/hide-delay (ms), events ncss-hovercard-show/-hide. Only put supplementary information in the card - touch users without interestfor will not see it.

Notifications

ncss.notify() creates a message in an <ncss-toast-region> (created automatically, one per position). Status colors brand/success/warning/danger, six positions (top-start … bottom-end), close button, timer that pauses on hover, focus or a background tab (the remaining time continues). Errors stay until dismissed by default. The region is aria-live="polite", danger/warning add role="alert"; as popover="manual" it sits in the top layer, above modal dialogs too.

ncss.notify("Saved", { status: "success" });
ncss.notify({ title: "Upload failed", message: "File too large", status: "danger" });
ncss.notify("Copied", { position: "bottom-end", stack: true, timeout: 8000 });
// without the global object:
document.dispatchEvent(new CustomEvent("ncss-notify", { detail: { message: "Hello" } }));
<button type="button" data-ncss-notify="Saved" data-status="success">Save</button>

<!-- server-rendered, simply stays visible without JS -->
<ncss-toast-region position="top-end" stack>
  <div class="ncss-notification ncss-notification--success" data-timeout="6000">
    <p class="ncss-notification-title">Saved</p>
    <p>Your changes are live.</p>
  </div>
</ncss-toast-region>
<script src="ncss/js/notification.js" defer></script>

Stacked (attribute stack or option stack: true): older messages pile up behind the newest one and fan out on hover or keyboard focus. Message text is always inserted as text (never HTML) - pass a DOM node for custom markup. Built-in texts follow <html lang> (German/English).

Aurora & mesh

Soft, drifting color fields from the brand colors behind a section - radial gradients moved with transform only (no blur filter). Text stays --ncss-color-text on colors mixed with the page surface, in light and dark.

<section class="ncss-aurora">...</section>
<section class="ncss-aurora ncss-aurora--vivid">...</section>
<section class="ncss-mesh">...</section>
<section class="ncss-mesh ncss-mesh--static">...</section>

Tokens: --ncss-aurora-1/-2/-3, --ncss-aurora-opacity, --ncss-aurora-speed (14s), --ncss-mesh-speed (28s). Static with reduced motion, off in forced colors.

Command palette as search (search mode)

For large lists - such as a site search - <ncss-command-palette src="search.json"> loads its entries from a JSON file the first time the palette opens and renders results only while typing: ranked (title start before title before keyword/text), limited per group (limit, default 8), the group with the best hit first, search terms highlighted with <mark>. No server, no library - the search at the top of this website is exactly that (index built by docs-src/build.mjs).

<button type="button" command="show-modal" commandfor="search">Search <kbd data-ncss-command-key>Ctrl K</kbd></button>
<ncss-command-palette shortcut="k" slash src="search.json" limit="7">
  <dialog id="search" class="ncss-command" aria-label="Search" closedby="any">
    <div class="ncss-command-search"><input class="ncss-command-input" type="search" aria-label="Search"></div>
    <div class="ncss-command-list" aria-label="Results">...suggestions (also without JS)...</div>
    <p class="ncss-command-empty" hidden>No results</p>
  </dialog>
</ncss-command-palette>
{ "groups": [{ "id": "pages", "label": "Pages" }, { "id": "classes", "label": "Classes" }],
  "items":  [{ "g": "pages", "t": "Cards", "u": "en/cards.html", "h": "Content", "s": "Short excerpt", "k": "card teaser" }] }
Attribute / APIMeaning
srcJSON index for search mode; u is relative to the JSON file.
limitMaximum results per group (default 8).
slashAlso / as a shortcut (not while a text field has focus).
data-ncss-command-keyElement receives the matching shortcut text (⌘K or Ctrl K).
.ncss-command-item-title / -snippetTwo-line result: title and a one-line excerpt.
