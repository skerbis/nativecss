Section Navigation

For long pages with several sections - one-pagers, product pages, docs pages: a second, slim bar right below the main navigation. It sticks while scrolling, shows the sections in a single row (swipeable on narrow screens) and highlights the section currently in view. This page uses it itself - right below the top bar.

Markup

Place it right after the top bar as a sibling inside <body> (not inside <main>) - only then does it stick across the whole page. Targets are plain IDs.

<header class="ncss-topbar">...</header>
<nav class="ncss-subnav" aria-label="On this page" data-ncss-subnav>
  <div class="ncss-subnav-inner">
    <span class="ncss-subnav-label" aria-hidden="true">On this page</span>
    <ul class="ncss-subnav-list" role="list">
      <li><a href="#rooms">Rooms</a></li>
      <li><a href="#offers">Offers</a></li>
      <li><a href="#request">Request</a></li>
    </ul>
  </div>
</nav>
<main>
  <section id="rooms"><h2>Rooms</h2>...</section>
  ...
</main>
<script src="ncss/js/subnav.js" defer></script>

Classes & attributes

ClassPurpose
.ncss-subnavSticky "On this page" bar below the top bar, one row of jump links to the sections.
.ncss-subnav-innerInner frame at container width (same alignment as the page content).
.ncss-subnav-labelVisible caption before the links, hidden from screen readers (the nav carries aria-label).
.ncss-subnav-listThe link list: swipeable with soft edges, current link highlighted as a pill.
[data-ncss-sticky-header]Shared sticky container for top bar + bar; the bar no longer sticks on its own inside it, js/subnav.js measures its height.
[data-ncss-subnav]Enables js/subnav.js: sets aria-current="location" on the link of the section in view and keeps it scrolled into the bar.

With your own header: one sticky unit

If the bar sticks on its own below a top bar, its top offset must match the top bar's height exactly - when the header grows (logo, font size, 200 % zoom, mobile menu), the bar slides under it while scrolling. Robust: put the top bar AND the bar into ONE sticky container and mark it with data-ncss-sticky-header. Only the container sticks, both rows always move together, and js/subnav.js measures its height for the jump offset (--ncss-scroll-offset). This website uses exactly this pattern.

<div class="site-head" data-ncss-sticky-header>
  <header class="ncss-topbar">...</header>
  <nav class="ncss-subnav" aria-label="On this page" data-ncss-subnav>...</nav>
</div>
.site-head { position: sticky; inset-block-start: 0; z-index: var(--ncss-topbar-z); }
.site-head > .ncss-topbar { position: relative; } /* only the container sticks */

Behavior

  • Offset: :root automatically gets scroll-padding-block-start = top bar + this bar - jumped-to headings land visibly below both bars, also for keyboard navigation and links from other pages.
  • Current section: natively via scroll-target-group + :target-current (Chromium 140+, pure CSS); js/subnav.js adds aria-current="location" everywhere (IntersectionObserver) so screen readers know the state too. Without JS: plain jump links.
  • Motion: smooth scrolling comes from reset.css and is off with prefers-reduced-motion.
  • Mobile: the main bar collapses into the menu button, the section bar stays a single swipeable row.
  • Forced colors / print: current link gets a system-colour outline; hidden in print.

Parameters

TokenPurpose
--ncss-subnav-heightHeight of the bar (default 2.75rem), part of the jump offset.
--ncss-subnav-topDistance from the top (default --ncss-topbar-height); 0 on pages without a sticky top bar.
--ncss-scroll-offsetHeight of the sticky header area measured by js/subnav.js - basis for scroll-padding and your own sticky offsets.
