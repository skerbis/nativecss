CMS integration

NativeCSS is plain CSS plus individual, optional scripts - any CMS that can print a <link> line can use it. This page shows the usual way for each system, how to set your own brand values via theme.css, and how to load only what a page needs.

The basic pattern (applies everywhere)

  1. Get the files: release ZIP from GitHub (only dist/), CDN or npm i @skerbis/nativecss - see Quick start.
  2. Include: ncss.css (everything) or a trimmed copy with only the @import lines you need, then theme.css for your own values.
  3. Scripts only where needed: every component with behaviour has exactly one file in dist/js/ - include it only where the component is used. The code inspector (bottom right) shows which file each element needs.
  4. Content loaded later (front-end editing, AJAX, htmx): fire ncss-content-change after inserting - see Dynamic content.
<link rel="stylesheet" href="/assets/ncss/ncss.css">
<link rel="stylesheet" href="/assets/ncss/theme.css">
<!-- only on pages with dialogs, tabs, players … -->
<script src="/assets/ncss/js/dialog-light-dismiss.js" defer></script>

CMS design settings (colour, font, radius from a back-end form) map perfectly onto the seed values in theme.css: the CMS only writes a small unlayered file or a <style> block with --ncss-… values on :root; NativeCSS derives all other steps itself - see Theming.

REDAXO 6 + fluid

The AddOn fluid ships a ready NativeCSS kit: switch under Website → Kit → NativeCSS, content stays. Editors work directly on the page (blocks, design templates, colours, fonts); the kit loads only the CSS/JS files of the blocks a page uses.

  • Blocks using NativeCSS components: "Video & Audio" (<ncss-video-player> with chapters and captions, <ncss-audio-player> with playlist), "Before/After" (<ncss-compare>), key figures with count-up, logos as a marquee, scrollytelling, background video in the hero.
  • Reveal effect as a section setting (None · Fade · From below · Circle · Curtain) - default "None", automatically off with reduced motion.
  • Update to a new NativeCSS version: php bin/console fluid:kit:ncss-update --tag=v1.1.0 (or --from=/path/to/nativecss); shows new/changed files and records the version.

REDAXO 5 (classic)

Copy dist/ e.g. to assets/ncss/ (or the assets folder of a project/theme AddOn) and include it in the template:

<link rel="stylesheet" href="<?= rex_url::base('assets/ncss/ncss.css') ?>">
<link rel="stylesheet" href="<?= rex_url::base('assets/ncss/theme.css') ?>">
  • Modules output plain NativeCSS markup (card, accordion with <details>, dialog …) - no wrapper classes needed.
  • Existing UIkit modules can be converted with the UIkit→NativeCSS converter; PHP in the module code stays untouched (command line: node tools/uikit-to-ncss/convert.mjs modules/ --write).
  • Theme values from the database (e.g. design settings of a theme AddOn): print a small <style>:root{--ncss-color-brand: …}</style> block AFTER the two files.

WordPress

Put the files into ncss/ in your (child) theme and enqueue them in functions.php - for the front end and the block editor:

add_action('wp_enqueue_scripts', function () {
    wp_enqueue_style('nativecss', get_theme_file_uri('ncss/ncss.css'), [], '1.1.0');
    wp_enqueue_style('nativecss-theme', get_theme_file_uri('ncss/theme.css'), ['nativecss'], '1.1.0');
});

// same look in the block editor
add_action('after_setup_theme', function () {
    add_theme_support('editor-styles');
    add_editor_style(['ncss/ncss.css', 'ncss/theme.css']);
});
  • theme.json: point the colour palette to NativeCSS tokens ("color": "var(--ncss-color-brand)") so the editor colour picker and the NativeCSS theme share one source.
  • Block styles/patterns: custom block styles can simply set NativeCSS classes (e.g. ncss-card); patterns deliver ready NativeCSS markup.

TYPO3

Put the files into your site package under Resources/Public/ncss/ and load them in the Fluid page template:

<f:asset.css identifier="nativecss" href="EXT:sitepackage/Resources/Public/ncss/ncss.css" />
<f:asset.css identifier="nativecss-theme" href="EXT:sitepackage/Resources/Public/ncss/theme.css" />

Content element templates (Fluid) output NativeCSS markup; load component scripts with <f:asset.script> only in the templates that need them.

Contao, Kirby and others

  • Contao: put dist/ into the theme folder under files/, add it as external stylesheets in the page layout or print it in your own page template; content element templates deliver NativeCSS markup.
  • Kirby: <?= css(['assets/ncss/ncss.css', 'assets/ncss/theme.css']) ?> in the header snippet; blocks/snippets output NativeCSS markup.
  • Statamic, Craft, Joomla, Drupal …: the same pattern - two <link> lines in the layout, markup in the component templates, scripts only where needed.
