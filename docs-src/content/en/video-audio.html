Video & Audio

Moving images and sound beyond the native elements - every component is its own CSS file plus at most one script, usable on its own (only tokens.css/colors.css required). Without JS the native <video>/<audio> stays fully usable everywhere. Live example: Video & Audio demo. Basics (aspect ratio, object-fit, hero): Media.

The web components are plain light-DOM elements (no shadow root) - page CSS and theme.css apply as usual. If a required browser API is missing, the element is never defined and stays on its native fallback. Labels and announcements follow <html lang> (German/English).

Video player

The video and audio players are one family: the same icons, a round play button in the accent colour (--ncss-color-brand), the same 0.3rem seek bar with chapter gaps, the same chapter and playlist lists and menus. On video the controls float frameless on a soft gradient over the picture (fixed white there so they read on any frame); card, lists and menu follow the page theme.

<!-- Stage only -->
<ncss-video-player>
  <video controls playsinline preload="metadata" poster="poster.jpg">
    <source src="film.mp4" type="video/mp4">
    <track kind="captions" src="en.vtt" srclang="en" label="English" default>
    <track kind="captions" src="de.vtt" srclang="de" label="Deutsch">
    <track kind="chapters" src="chapters.vtt" srclang="en">
  </video>
</ncss-video-player>

<!-- Card with chapter list and playlist (like the audio card) -->
<ncss-video-player layout="card">
  <video controls playsinline preload="metadata" poster="film.jpg">...</video>
  <p class="ncss-video-player-title">Four moods</p>
  <p class="ncss-video-player-meta">Short film</p>
  <ol class="ncss-video-player-playlist">
    <li><a href="film.mp4" data-poster="film.jpg" data-title="Four moods"
           data-chapters="chapters.vtt" data-captions="en=en.vtt de=de.vtt">
      <img src="film.jpg" alt=""><span>Four moods</span> <span>0:32</span></a></li>
    <li><a href="scene.mp4" data-poster="scene.jpg" data-title="Northern lights">
      <img src="scene.jpg" alt=""><span>Northern lights</span> <span>0:10</span></a></li>
  </ol>
</ncss-video-player>

Adds a big play button, a seek bar with buffered ranges, chapter gaps and a time/chapter pill under the pointer, the current chapter, mute + an expanding volume slider, a CC toggle, one settings menu (gear: speed + caption language; a non-default speed shows as a badge on the gear), picture-in-picture, fullscreen on the stage (custom bar and captions come along), auto-hiding controls and cursor, a loading spinner and an error state. layout="card" adds a column with title, a clickable chapter list (current chapter highlighted) and a playlist (thumbnail, title, duration, previous/next, auto-advance) - beside the picture when there is room, below it otherwise (wraps without a breakpoint). Media Session: title and poster appear in the system media controls.

speeds="0.5 0.75 1 1.25 1.5 2"Speed entries in the settings menu

Keyboard (focus inside the player): Space/K play-pause, J/L -/+10 s, arrow left/right -/+5 s, arrow up/down volume, M mute, F fullscreen, C captions, N/P next/previous video, 0-9 jump to 0-90 %, Home/End, < and > speed. Seek bar and volume are real <input type="range"> elements, the menu is a popover with role="menu" and groups; state changes are announced through a polite live region.

One player at a time: when a video or audio player starts, all others pause - via the data-ncss-player-media attribute convention, without a shared script. Background and scroll videos are excluded. Same look, separate files: the values are deliberately duplicated in video-player.css and audio-player.css, so each file still works on its own.

Audio player

<!-- Compact, one line -->
<ncss-audio-player>
  <audio controls preload="metadata" src="episode.m4a"></audio>
</ncss-audio-player>

<!-- Card with waveform, chapters and playlist -->
<ncss-audio-player layout="card" waveform>
  <img class="ncss-audio-player-cover" src="cover.svg" alt="">
  <p class="ncss-audio-player-title">Tide</p>
  <p class="ncss-audio-player-artist">Ensemble</p>
  <audio controls preload="metadata" src="tide.m4a">
    <track kind="chapters" src="tide-chapters.vtt" srclang="en">
  </audio>
  <ol class="ncss-audio-player-playlist">
    <li><a href="dawn.m4a" data-title="Dawn" data-artist="Ensemble"
           data-cover="dawn.svg">Dawn <span>0:32</span></a></li>
  </ol>
</ncss-audio-player>

Adds play/pause, -15/+30 s (text buttons), a seek bar with chapter marks, volume, speed, a clickable chapter list (card), an optional waveform instead of the track (waveform: the file is decoded once with Web Audio - same origin only, up to 8 MB), a playlist with previous/next and auto-advance, and Media Session (title and cover on the lock screen / system media controls, media keys). Without JS the native <audio controls> stays and playlist links are plain links to the files. Follows the page theme (light/dark).

Not to be confused with .ncss-audio/.ncss-audio-card from components/audio.css, which only style the native element (width, framed card with title) without any JS - both are independent.

Scroll-scrubbed video

Scrolling scrubs a video forwards and backwards. Pinned by default: the element becomes as tall as the scroll distance, the stage sticks in the viewport and the video fills it edge to edge (object-fit: cover - deliberately no black bars).

<ncss-scroll-video length="400">
  <div class="ncss-scroll-video-stage">
    <video muted playsinline controls preload="metadata" poster="poster.jpg" src="scrub.mp4"></video>
    <p class="ncss-scroll-video-caption" data-ncss-time="1-3">Text between 1 and 3 s</p>
  </div>
</ncss-scroll-video>
Attribute / propertyMeaning
length="300"Scroll distance in % of the viewport height (sets --ncss-scroll-video-length, in lvh - does not jump with the mobile address bar)
start, endTime range in seconds the distance maps to
smoothing="0.85"Lag (0 = direct, up to 0.98 = very soft)
inlineNot pinned - scrubs while the video crosses the viewport
--ncss-scroll-video-topStage offset from the top, e.g. var(--ncss-topbar-height) below a sticky top bar
--ncss-scroll-video-fit, --ncss-scroll-video-positioncover (default) or contain; visible part of the frame on tall screens
el.progress, el.time, el.active, event ncss-scroll-video-changeState for custom effects

Scrollytelling: inside <ncss-scrolly> the video follows the steps. data-ncss-time="2" on a .ncss-scrolly-step seeks to 2 s, data-ncss-time="2-4" scrubs from 2 to 4 s while the step crosses the trigger line. The position is computed from the steps' geometry; the element also listens to the ncss-scrolly-step event (detail.time) - under reduced motion it uses it to jump per step instead of scrubbing. Inside a scrolly figure it is inline automatically.

<ncss-scrolly>
  <div class="ncss-scrolly-steps">
    <div class="ncss-scrolly-step" data-ncss-time="0-2"><div>...</div></div>
    <div class="ncss-scrolly-step" data-ncss-time="2-4"><div>...</div></div>
  </div>
  <div class="ncss-scrolly-media">
    <figure class="ncss-scrolly-figure">
      <ncss-scroll-video><div class="ncss-scroll-video-stage"><video muted playsinline src="scrub.mp4"></video></div></ncss-scroll-video>
    </figure>
  </div>
</ncss-scrolly>

Inactive (a normal video with controls and poster, texts listed below it): without JS, under prefers-reduced-motion (except scrollytelling, see above), prefers-reduced-data or Save-Data. Seeking: at most one seek in flight, the next starts on seeked; fastSeek() only for large jumps, the final frame is always exact.

Image sequence instead of video

The same idea with single frames on a canvas - every frame is complete, so scrubbing is smooth in every engine (no decoding, no seeking). The robust choice when Safari stutter is not acceptable; costs more requests.

<ncss-scroll-frames src="frames/f-%03d.webp" count="72" length="300">
  <div class="ncss-scroll-frames-stage">
    <img class="ncss-scroll-frames-poster" src="frames/f-020.webp" alt="What the sequence shows"
         width="800" height="450">
    <div>Optional text over the image</div>
  </div>
</ncss-scroll-frames>

The <img> is the fallback (no JS, reduced motion, Save-Data) and provides the aspect ratio and alternative text for the <canvas role="img">. Attributes: src (%d/%03d = frame number), count, first="1", length, smoothing="0.6", fit="cover|contain", inline. Loading starts near the viewport, coarse first (every 16th frame), then refined; gaps are filled with the nearest loaded frame.

Background video

<section class="ncss-video-bg ncss-video-bg--dark" data-ncss-video-bg>
  <video class="ncss-video-bg-media" muted loop playsinline preload="none"
         poster="poster.jpg" aria-hidden="true">
    <source data-src="loop.webm" type="video/webm">
    <source data-src="loop.mp4" type="video/mp4">
  </video>
  <div>... content ...</div>
</section>
Class / attributePurpose
.ncss-video-bg--dark / --light / --brand / --gradientTint for readable text - also sets color-scheme, so tokens inside resolve accordingly (buttons, cards)
--ncss-video-bg-strengthTint opacity (default 55 %) - lower for dark footage, higher for bright footage
--ncss-video-bg-positionVisible part of the frame (object-position)
data-ncss-video-bg="top-end"Corner of the pause toggle (top-start, bottom-start, default bottom end)
Event ncss-video-bg-changedetail = { paused, user }

The script adds a visible pause/play toggle with a text label (WCAG 2.2.2: motion longer than 5 s needs a way to pause), loads only near the viewport (data-src → src), plays only while visible and pauses in a background tab. Under reduced motion, data saving or forced colors nothing is downloaded - only the poster, and the toggle offers "Play". Works the same on a .ncss-hero with the video inside .ncss-hero-media and replaces js/hero-video-motion.js there. No <source media> for different files per breakpoint - that is not cross-browser for video (see Media).

Video in text

<div class="ncss-video-text" data-ncss-video-bg>
  <video class="ncss-video-text-media" muted loop playsinline preload="none"
         poster="poster.jpg" aria-hidden="true">
    <source data-src="loop.mp4" type="video/mp4">
  </video>
  <h2 class="ncss-video-text-title">Colour flow</h2>
</div>

The headline stays real, selectable text. One blend mode for light and dark (mix-blend-mode: hard-light): 50 % grey lets the video show through the glyphs unchanged, the page colour (--ncss-color-bg) produces exactly that surface around them. Colourful mid-tone footage works best. data-ncss-video-bg + video-bg.css/.js add the pause toggle, lazy loading and reduced motion; without the script src + autoplay are enough. Size: --ncss-video-text-size (capped at 18cqi).

Mini player

<ncss-video-float>
  <div class="ncss-video-float-frame">
    <ncss-video-player><video controls ...></video></ncss-video-player>
  </div>
</ncss-video-float>

A playing video that scrolls out of view docks to a window corner (position="start" left, position="top-end" top) and returns when you scroll back; the element keeps its height as a placeholder. "Close" (or Esc) pauses and undocks; focus is never moved. Works with a bare <video> as well as <ncss-video-player>. API: el.dock(), undock(), docked; events ncss-video-float-dock/-undock.

Plays a muted preview while the card is hovered with a mouse or focused with the keyboard, then returns to the poster. preload="none": not a single video byte loads before that. Touch devices and reduced motion: nothing plays and the badge is hidden. Customisable: --ncss-video-card-ratio, --ncss-video-card-radius.

Encoding video for scrubbing

Scrubbing means seeking, and a seek can only start decoding at a keyframe. Regular web video has a keyframe every 2-10 s - Chrome copes, Safari visibly stutters. For scroll video make every frame a keyframe (all-intra, -g 1) or use a very short GOP. All-intra files are 2-4× larger: keep them short (6-10 s), at most 1280 px wide and silent.

# Scroll video: H.264, every frame a keyframe, no audio, metadata first
ffmpeg -i source.mov -an -vf "scale=1280:-2,fps=24" \
  -c:v libx264 -preset slow -crf 25 -g 1 -pix_fmt yuv420p \
  -movflags +faststart scrub.mp4

# Compromise: keyframe every 4 frames (about 35 % smaller, slightly less smooth in Safari)
ffmpeg -i source.mov -an -vf "scale=1280:-2,fps=24" \
  -c:v libx264 -preset slow -crf 27 -g 4 -keyint_min 4 -sc_threshold 0 \
  -pix_fmt yuv420p -movflags +faststart scrub-gop4.mp4

# Poster (a representative frame, here at 1.2 s)
ffmpeg -ss 1.2 -i scrub.mp4 -frames:v 1 -q:v 4 poster.jpg

# Image sequence for <ncss-scroll-frames>: 72 frames, 800 px wide
ffmpeg -i source.mov -vf "fps=72/8,scale=800:-2" -q:v 6 frames/f-%03d.jpg
#   (fps = frame count / seconds; WebP: with a libwebp build use -c:v libwebp -quality 70 f-%03d.webp)

# Background loop: regular GOP (2 s), silent, small - MP4 + WebM
ffmpeg -i source.mov -an -vf "scale=960:-2,fps=24" -c:v libx264 -preset slow -crf 28 -g 48 \
  -pix_fmt yuv420p -movflags +faststart loop.mp4
ffmpeg -i source.mov -an -vf "scale=960:-2,fps=24" -c:v libvpx-vp9 -crf 42 -b:v 0 -row-mt 1 -g 48 loop.webm

# Player video with sound
ffmpeg -i source.mov -vf "scale=1280:-2" -c:v libx264 -preset slow -crf 26 -g 48 \
  -pix_fmt yuv420p -c:a aac -b:a 128k -movflags +faststart film.mp4

# Audio for <ncss-audio-player>: AAC in M4A plays in every browser
ffmpeg -i source.wav -c:a aac -b:a 96k -movflags +faststart episode.m4a

Checklist: muted playsinline on every scroll and background video (iOS); -movflags +faststart so playback can begin before the whole file has loaded; the server must answer byte-range requests (206 Partial Content) - otherwise Safari refuses to play or seek (note: PHP's built-in dev server php -S does not answer range requests); a poster for the first paint and for reduced motion/Save-Data; seamless loops (first frame = the frame after the last).
