Cover (cropping embeds to fill)

For <img>/<video>, .ncss-img-cover above is enough (native object-fit). components/cover.css covers the one case object-fit does NOT reliably solve: <iframe> embeds (YouTube/Vimeo/Google Maps) - object-fit doesn't affect the embedded document in most browsers.

<div class="ncss-cover-container" style="height: 20rem;">
  <iframe class="ncss-cover" src="https://www.youtube.com/embed/..." title="..." allowfullscreen></iframe>
</div>

Technique: the classic min-width/min-height:100% + width/height:auto crop pattern (no object-fit) - needs an EXPLICIT aspect-ratio on the embedded element itself for this (default: --ncss-aspect-video, overridable via style="aspect-ratio: ..."). Relying on an <iframe>'s width/height HTML attributes instead gives NO aspect-ratio-accurate result on an absolutely positioned element (confirmed via a real test). .ncss-cover-container needs its own height supplied from outside (fixed, %, or e.g. inside a .ncss-hero) - unlike .ncss-ratio-video, which derives height from width.

Overlay (panel over image/video)

components/overlay.css - a panel over an image (caption, CTA, gradient scrim). For an entire page section with a background image: Hero Section below - Overlay is the smaller, media-local variant of the same underlying principle.

<div class="ncss-overlay-container">
  <img src="photo.jpg" alt="...">
  <div class="ncss-overlay ncss-overlay--bottom ncss-overlay--scrim">
    <p class="ncss-text-light">Caption</p>
  </div>
</div>
ClassPurpose
.ncss-overlayDefault: covers the whole area (inset: 0)
.ncss-overlay--top / --bottomOnly the top/bottom edge instead of the whole area
.ncss-overlay--centerCentered, at its own size (no padding) - e.g. for a centered play icon
.ncss-overlay--scrimGradient scrim (dark → transparent) - readable text over varying photo content, mirrors automatically with --top
.ncss-overlay--tintEven, semi-transparent fill instead of a gradient (--ncss-color-overlay)

Combines with existing ncss building blocks instead of duplicating them: .ncss-reveal-on-hover (Scroll & Visibility) for "only visible on hover" - works unchanged, because .ncss-overlay is a direct child of .ncss-overlay-container. .ncss-text-light/-dark (Typography) for text that should stay readable regardless of the image content.

Hero Section

Image background with content on top, components/hero.css.

<section class="ncss-hero">
  <div class="ncss-hero-media" style="background-image: url(image.jpg)"></div>
  <div class="ncss-hero-content ncss-hero-content--filled">
    <h2>Heading</h2>
    <p>Text...</p>
  </div>
</section>
.ncss-heroWrapper, min-height: 22rem, overflow: clip
.ncss-hero-mediaIts own layer for the background image (including a readability scrim) - always set background-image inline, never via a custom property, see Known Limitations
.ncss-hero-content--transparentText directly on the image (default)
.ncss-hero-content--filledText on an opaque card on top
.ncss-hero--parallaxImage moves slower than the content while scrolling, via animation-timeline: view() - no JS, no background-attachment: fixed (deliberately never supported on iOS Safari)

Background video instead of an image

The same .ncss-hero-media, now with a real <video> child instead of background-image - object-fit: cover works reliably for <video> (unlike <iframe>, see Cover above), no special cropping needed:

<div class="ncss-hero-media">
  <video src="clip.mp4" autoplay muted loop playsinline poster="frame.jpg"></video>
</div>

autoplay NEEDS muted (otherwise virtually every browser blocks autostart), playsinline prevents fullscreen takeover on iOS Safari, poster shows a still frame before loading. For prefers-reduced-motion: pure CSS can't control <video> playback (unlike the animation-timeline used by --parallax above) - js/hero-video-motion.js (opt-in, only include it on pages with an actual background video) removes autoplay and pauses the video when that preference is active; the video stays visible (poster/last frame), just without automatic motion:

<script src="js/hero-video-motion.js" defer></script>

Arrows and dots for the slideshow (new)

.ncss-slideshow--controls adds arrow buttons and dots to the scroll-snap slideshow. Where the browser supports ::scroll-button() and ::scroll-marker (Chromium 135+), it generates both itself - no JavaScript at all. Safari and Firefox get the same controls from js/slideshow.js as real <button>s. The script checks the same conditions as the CSS and only builds what is missing natively: there are never two sets of arrows or dots. The arrows move by one item and are disabled at the start or end. The current dot is marked (aria-current from the script, natively as the selected tab). .ncss-slideshow--shadow lays a shadow over the photos at an edge as long as there is more in that direction.

Several images side by side (--peek) with optional autoplay - the button stops it, mouse or focus inside the slideshow pause it as well:

 
<ncss-slideshow class="ncss-slideshow ncss-slideshow--controls ncss-slideshow--shadow">
  <ul class="ncss-slideshow-track" tabindex="0" aria-label="Hotel Seeblick, four photos">
    <li class="ncss-slideshow-item"><img src="see-panorama.webp" alt="Panorama of the lake with mountains"></li>
    <li class="ncss-slideshow-item"><img src="spa-pool.webp" alt="Indoor pool with large lattice windows"></li>
    ...
  </ul>
</ncss-slideshow>

<!-- Optional: autoplay every 6 seconds, off by default -->
<ncss-slideshow class="ncss-slideshow ncss-slideshow--controls" autoplay="6000">...</ncss-slideshow>

<script src="js/slideshow.js" defer></script>
Class / attributePurpose
.ncss-slideshow--controlsArrows + dots: native via ::scroll-button()/::scroll-marker, otherwise from js/slideshow.js
.ncss-slideshow--shadowEdge shadows over the photos as long as there is more in that direction (scroll-driven animation; in Safari and with reduced motion via the script)
<ncss-slideshow>Wrapper as a custom element - needed for the script fallback and autoplay; a <div> still works, then native only
autoplay="6000"Automatic advance (milliseconds, off by default) with a pause button; stops on hover and focus, does not start with reduced motion
data-label-prev, -next, -dots, -dot, -play, -pauseOverride labels (on the track); default German/English by <html lang>, -dot with {n} and {total}
ncss-slideshow-change, -play, -pauseEvents (bubbling); detail.index on change. Methods: next(), prev(), goTo(i), play(), pause()

Accessibility: The track stays reachable by Tab and scrollable with the arrow keys (put tabindex="0" and aria-label in the markup). Arrows and dots are real buttons with names such as "Next item" or "2 of 4"; the arrows stay focusable at the end (aria-disabled) so focus is never lost. Autoplay is off until you switch it on; its pause button comes before the images in the DOM (WCAG 2.2.2). With reduced motion the slideshow jumps instead of gliding, in forced-colors mode the dots get system colors. Without JavaScript (and without native support) swiping and scrolling work as before.
