Forms

Real <input>, <select> and <textarea>, fully styled – no imitations. The browser does the validation, error messages are linked to their fields, and at the end there is a complete booking request for Hotel Seeblick. Use the Inspect button at the bottom right (or Alt+I), then click a block.

One field: label, input, hint

.ncss-field stacks label, field and hint. The asterisk from --required is only visual – required on the field and an explanatory sentence before the form belong with it. Link hints via aria-describedby so they are read out on focus.

Note: placeholder is not a label – it disappears as you type. Every field needs a real <label>.

  • .ncss-field
  • .ncss-label
  • .ncss-label--required
  • .ncss-input
  • .ncss-textarea
  • .ncss-field-hint

Validation and error messages

The browser checks required, type="email", pattern and friends itself. A field only turns red after input or a submit attempt (:user-invalid) – not on page load. When the server reports errors, add aria-invalid, a linked error text and a summary with jump links.

Note: ncss only colours :user-invalid. For [aria-invalid="true"] the page adds one line of CSS itself.

  • :user-invalid
  • .ncss-field-error
  • aria-invalid
  • aria-describedby
  • .ncss-alert--danger

Checkbox, radio and switch

Checkbox and radio stay native and only get the brand colour and alignment. The switch is a redrawn checkbox – with role="switch" it is also announced as a switch. Related options sit in a <fieldset> with a <legend>: the legend is the question.

  • .ncss-choice
  • .ncss-switch
  • role="switch"
  • <fieldset>
  • <legend>

Select with a styled drop-down

A normal <select> in a wrapper that draws the arrow. In Chrome and Edge the drop-down itself is styled via appearance: base-select – options may even contain icons there. In Firefox and Safari js/combobox.js provides the same look.

Note: Always include <button><selectedcontent> as the first child – it makes the behaviour consistent across browsers. Text stays mandatory; icons are only an addition.

  • .ncss-select-wrapper
  • .ncss-select
  • <selectedcontent>
  • js/combobox.js
In the handbook: Select →

Combobox: type or pick

<input list> with a <datalist> allows free input and suggests matching values. The browser’s suggestion list cannot be styled in any browser – js/combobox.js replaces it with a filtered, styled list. Without the script the native list remains.

  • <input list>
  • <datalist>
  • .ncss-combobox
  • .ncss-combobox-list

Input group: merging fields

A field and a button – or two fields – visually become one: a shared border, only the outer corners rounded. Purely visual, no semantics.

Note: The label goes before the group, not inside it – otherwise the corner rounding lands on the hidden label. For two fields without room for labels: aria-label directly on the field.

  • .ncss-input-group
  • .ncss-visually-hidden

Floating labels

The label sits in the empty field like a placeholder and slides up on focus – but stays a real <label>. Pure CSS via :has() and :placeholder-shown.

Note: placeholder=" " (a single space) is required, otherwise CSS cannot detect the empty field. On a <select> the label always sits at the top.

  • .ncss-field--floating
  • placeholder=" "
In the handbook: floating labels →

Date, time, number, colour

All through the same .ncss-input rule, with small additions where browsers bring their own parts: calendar and clock icons follow the light/dark theme, the colour field gets the ncss corners. The arrows on the number field stay – they are real functionality.

All together: booking request

A whole form on a grid: .ncss-grid places fields side by side while there is room and stacks them on phones. Groups sit in a <fieldset>, the room choice is real radio buttons with pictures, and autocomplete fills in contact details.

Note: The example uses method="dialog" so nothing is sent – in real life it says method="post" with an action.

  • .ncss-grid
  • --ncss-grid-min
  • <fieldset>
  • autocomplete
