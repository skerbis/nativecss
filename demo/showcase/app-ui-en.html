App UI

Building blocks for dashboards and admin interfaces – all shown with “ImmoDesk”, the fictional property manager. Almost everything is pure CSS; upload, countdown and removable tags each bring a small script. Use the Inspect button at the bottom right (or Alt+I) and click any block to see its markup.

Elsewhere in the tour: floating labels under Forms, “back to top” under Navigation, badges under Content.

App shell

Sidebar, top bar, content – without a line of JS. The sidebar is a native popover: from 48rem container width it stands as a column, below that the same element becomes an off-canvas behind the menu button.

Watch out: Embedded like this, the shell needs its own scroll box and --ncss-app-shell-height set to its height – otherwise its top bar sticks to the page instead of the box.

  • .ncss-app-shell
  • -sidebar[popover]
  • -topbar
  • -content
  • -nav
  • -toggle
  • --ncss-app-shell-height
  • --ncss-app-shell-sidebar-width

Dense variants

Admin interfaces show a lot in little space: buttons in three sizes, square icon buttons, a compact table (see the app shell above) and cards with fixed, small padding.

Watch out: An icon button has no visible word – aria-label is mandatory.

  • .ncss-btn--sm
  • .ncss-btn--lg
  • .ncss-btn--icon
  • .ncss-table--compact
  • .ncss-card--compact

Avatar

Initials (or an image) in a circle, in four sizes and the badge colours. The group overlaps – for “who is working on this”.

Watch out: If the name is printed next to it anyway, use aria-hidden="true" instead of role="img" – otherwise it is read twice.

  • .ncss-avatar
  • --sm
  • --lg
  • --xl
  • --brand-2 … --danger
  • .ncss-avatar-group
  • --ncss-avatar-ring

Tags & chips

A badge is a status, a tag is content: keyword, filter chip or removable value. Filter chips are buttons whose state lives only in aria-pressed – the styling follows the attribute.

Try it: click “Commercial” – no ticket matches, and the empty state is announced.

  • .ncss-tag
  • --brand … --danger
  • --sm
  • [aria-pressed]
  • .ncss-tag-remove
  • data-ncss-dismiss

Stats with sparkline

Label, value, trend – and optionally a sparkline below. js/sparkline.js draws it from data-values or a JSON file (data-src) and adds the real values as a hidden table for screen readers.

Watch out: The arrow is silent – the direction (“Up by”) must be text in the markup. Where less is better (vacancy, outstanding items), --inverse swaps the colours.

  • .ncss-stat
  • -label
  • -value
  • -trend--up/--down/--flat
  • .ncss-stat--inverse
  • .ncss-sparkline
  • --success
  • --danger
  • data-ncss-count-up

Empty state

Instead of a silent, blank area: a short note and the next sensible action. --compact fits into cards and table cells (as with the filter chips above).

Watch out: If the state only appears after an action, set role="status" – otherwise a screen reader notices nothing.

  • .ncss-empty
  • -icon
  • -title
  • -actions
  • .ncss-empty--compact

Segmented control

Looks like a button bar but is a perfectly normal radio group: arrow keys, form submission and announcements (“2 of 3”) come from the browser. Here it even switches the view via :has() – no JS.

Watch out: Every <input> sits directly before its <label>.

  • .ncss-segmented
  • --sm
  • --block

Upload area

<ncss-dropzone> wraps a real <input type="file">: drag & drop, a file list with preview and remove. Uploading still happens through the native field – without JS it simply stays visible.

Try it: drag in an image or PDF – nothing leaves the browser, the demo submits no form.

  • <ncss-dropzone>
  • .ncss-dropzone-area
  • .ncss-dropzone-hint
  • data-ncss-max-size
  • ncss-dropzone-change
In the handbook: Upload area →

Spinner

A ring in currentColor – fits into any button and onto any surface. Inside a button, the button carries the state (aria-busy); the spinner is just visuals. With reduced motion it stands still.

Watch out: A standalone spinner with role="status" is only announced if it is inserted while loading.

  • .ncss-spinner
  • --sm
  • --lg
  • aria-busy

Countdown

<ncss-countdown> counts down to a point in time; digits and units come from Intl.NumberFormat according to lang – no translation table. Without JS, the date simply stays there.

Watch out: The ticking tiles are silent for screen readers; a role="timer" line carries the remaining time in words, updated every minute, and the end is announced.

  • <ncss-countdown>
  • datetime
  • .ncss-countdown--compact
  • data-ncss-units
  • data-ncss-done-text
  • ncss-countdown-end
